# M11.02. Строит винтажный анализ по когортам выдачи

Умение: G1
Модуль: M11
Требуется до этого: `step-01.md` этого модуля
Новые файлы, объявляемые этим шагом: `program\M11\work\vintage.py`;
`program\M11\work\vintage.csv` — 5 строк
Время: 4–5 ч

## 1.1. Цель и связь с умением

Продолжение G1: винтажный анализ — качество портфеля по когорте
**выдачи** (месяц, когда заём был выдан), а не по календарному месяцу
наблюдения. Это различие — предмет самого шага (1.6).

## 1.2. Теория своими словами

**Винтаж группирует по происхождению, не по времени наблюдения.**
Если сгруппировать займы по месяцу, в котором ОНИ ПРОСРОЧЕНЫ, разные
когорты выдачи смешиваются в одной цифре, и невозможно сказать, какая
именно партия выдач была рискованнее. Винтаж фиксирует когорту раз и
навсегда по дате выдачи, затем меряет её же исходы в одной и той же
точке возраста (здесь — 60 дней от due_date) для всех когорт — только
так когорты сравнимы друг с другом.

**Возраст, а не календарь.** Сравнивать январскую когорту в её
60-дневном возрасте с июньской в ЕЁ 60-дневном возрасте — единственный
способ дать обеим одинаковый шанс просрочиться. Сравнение «январь на
дату выгрузки» с «июнь на дату выгрузки» несопоставимо: у января было
семь месяцев на просрочку, у июня — меньше.

## 1.3. Разобранный пример на сквозном датасете

Прогон на машине автора 2026-08-20.

```python
mature = loans[loans["age_days"] >= 60].copy()
mature["cohort"] = mature["origination_date"].dt.strftime("%Y-%m")
mature["is_60plus"] = (mature["resolution_days"] > 60) | mature["resolution_days"].isna()
vintage = mature.groupby("cohort")["is_60plus"].mean()
```

```
2026-01: 0.0391 (n=358)
2026-02: 0.0256 (n=313)
2026-03: 0.0432 (n=347)
2026-04: 0.0475 (n=358)
2026-05: 0.0308 (n=227)
```

Июньская когорта отсутствует — на дату выгрузки (2026-08-01) её займы
(due_date до 2026-07-14) не достигли 60-дневного возраста (последний
due_date июня — не позднее 2026-07-14, +60 = не раньше 2026-09-12, это
позже даты выгрузки).

Заметный рост доли в апреле (4.75%) относительно февраля (2.56%) —
почти вдвое — стоит того, чтобы проверить, не менялась ли политика
одобрения или маркетинговый канал именно в этот период (за пределами
данных этого модуля, но именно так винтаж используется на практике —
как сигнал, куда смотреть дальше).

## 1.6. Типичные ошибки

**Ошибка:** группирует по месяцу, в котором зафиксирована просрочка
(месяц контрольной точки), а не по месяцу выдачи займа.
**Почему выглядит правильно:** оба варианта дают таблицу «месяц →
доля просрочки», выглядят как один и тот же винтажный анализ.
**Почему неправильно:** группировка по месяцу наблюдения смешивает
займы из разных когорт выдачи в одной строке — теряется именно то, что
винтаж должен показать: какая партия выдач была рискованнее. Числа при
такой группировке не совпадают с эталоном ни по одной из 5 строк.
**Как правильно:** группировка строго по `origination_date`, не по
дате просрочки, не по дате выгрузки.

## 1.8. Вопрос уровня собеседования

**Вопрос:** «Почему для сравнения когорт нельзя просто взять текущую
долю просрочки на дату отчёта по каждому месяцу выдачи?»

**Эталон (ответ покрывает ≥3 из 4 пунктов):**
1. У более старых когорт было больше времени накопить просрочку —
   сравнение на дату отчёта систематически занижает риск свежих когорт.
2. Нужна фиксированная точка возраста (например, 60 дней от due_date)
   одинаковая для всех когорт, чтобы сравнение было честным.
3. Слишком свежие когорты (не достигшие нужного возраста) должны быть
   исключены из сравнения целиком, а не занижать показатель нулём.
4. Называет практическое следствие: винтаж на фиксированном возрасте
   показывает тренд качества выдачи по времени, а не смесь возраста
   когорты и качества, слитых в одно число.
