# M9.04. Разбирает 10 ловушек про устройство A/B-экспериментов

Умение: F2
Модуль: M9
Требуется до этого: `step-03.md` этого модуля
Новые файлы, объявляемые этим шагом: `program\M9\work\traps_c_answers.md`
Время: 4–5 ч

## 1.1. Цель и связь с умением

Продолжение F2, готовит к F3 (`step-06.md`): эта группа разбирает не
статистику результата, а устройство самого эксперимента — то, что
ломается ещё до того, как посчитан хоть один p-value.

## 1.2. Теория своими словами

**Тест может быть статистически безупречен и всё равно неверен — из-за
того, как он устроен, а не как посчитан.** Sample Ratio
Mismatch, интерференция между группами, дисбаланс до старта: ни одно
из этих искажений не видно в самой формуле значимости. Все три
обнаруживаются только проверкой предпосылок эксперимента.

## 1.3. Разобранный пример — все 10 ловушек группы

Прогон `traps_c.py` на машине автора 2026-08-20.

**C21. Неравное распределение трафика.**
```
Вопрос: Трафик 90/10 вместо 50/50. Тест некорректен?
Датасет: control n=1800 (10.4%), treatment n=200 (12.5%), z=0.86
Неверный ответ: да, неравное разбиение искажает результат
Правильный ответ: оценка эффекта остаётся несмещённой, но мощность
  ниже — при том же трафике меньшая группа даёт более широкий ДИ
```

**C22. Интерференция между группами.**
```
Вопрос: Скидка тестируется на treatment, продавцы видят общий спрос.
  Control упал — акция вредит бизнесу?
Неверный ответ: да, control упал — акция вредит общим продажам
Правильный ответ: нет прямого вывода — при ограниченном запасе
  покупки treatment вытесняют доступность для control, метрика на
  уровне пользователя занижает эффект на уровне системы
```

**C23. Дисбаланс групп до старта.**
```
Вопрос: После теста treatment выше control на 120 грн. Эффект
  изменения?
Датасет: ДО теста control 1001, treatment 1098 — разница 97 грн уже
  существовала
Неверный ответ: да, разница 120 грн — эффект изменения
Правильный ответ: нет — верная оценка эффекта: разница разниц
  (after-before) для каждой группы, а не сырая разница итогов
```

**C24. Метрика-прокси вместо цели.**
```
Вопрос: 'Время на сайте' выросло на 25%. Продукт успешен?
Неверный ответ: да, рост вовлечённости — хороший знак
Правильный ответ: нет — время на сайте может расти из-за усложнённой
  навигации; смотреть надо метрику, ради которой прокси выбрана
```

**C25. Sample Ratio Mismatch.**
```
Вопрос: Задано 50/50, по факту 5300/4700 (разница 6%). Анализировать
  как есть?
Датасет: ожидалось 5000/5000, хи-квадрат=36.0 (порог значимости 3.8415)
Неверный ответ: да, 6% — в пределах случайных колебаний
Правильный ответ: нет — SRM, хи-квадрат намного выше порога 3.8415
  (это 1.9600², одна степень свободы; вывод — `step-01.md`, 1.2);
  указывает на баг в распределении трафика, результаты не заслуживают
  доверия
```

**C26. Утечка через общий граф пользователей.**
```
Вопрос: Новая лента рекомендаций, control видит посты друзей из
  treatment. Результат корректен?
Неверный ответ: да, каждая группа видит свою версию продукта
Правильный ответ: нет — утечка через соцсеть размывает эффект; нужна
  рандомизация по кластерам (география, изолированные сообщества)
```

**C27. Сезонное событие внутри теста.**
```
Вопрос: Тест шёл в Чёрную пятницу, рост выручки 40%. Эффект изменения?
Неверный ответ: да, рост однозначно от изменения
Правильный ответ: при корректной рандомизации сезонность действует на
  обе группы одинаково — проблема не в самом периоде, а в переносе
  результата на обычные периоды, поведение в акцию нетипично
```

**C28. Значимость при ничтожном размере эффекта.**
```
Вопрос: n=100000+100000, z=2.2 (значимо). Внедрять?
Датасет: control 10.00%, treatment 10.30%, абсолютная разница 0.30%
Неверный ответ: да, значимость подтверждена
Правильный ответ: 0.30 п.п. может не окупать затрат на внедрение — при
  очень больших выборках даже пренебрежимый эффект статистически значим
```

**C29. Cherry-picking метрики постфактум.**
```
Вопрос: Из 7 метрик анонсирован успех по одной (z=1.97), остальные не
  изменились. Отчёт готов?
Датасет: 7 метрик без эффекта ни в одной, максимальный |z|=1.97
Неверный ответ: да, нашли метрику, где эффект есть
Правильный ответ: нет — при проверке 7 метрик без поправки вероятность
  случайной значимости заметно выше 5%; метрика фиксируется до старта
```

**C30. Относительный прирост на маленькой базе.**
```
Вопрос: Конверсия выросла с 0.2% до 0.3% — заголовок «+50%!» корректен?
Датасет: абсолютный прирост 0.1 п.п.
Неверный ответ: да, рост 50% — впечатляющий результат
Правильный ответ: формально верно, но вводит в заблуждение без
  абсолютных чисел — заголовок должен нести оба числа
```

## 1.6. Типичные ошибки

**Ошибка:** C21 в первой версии скрипта дала отрицательный z (z=-1.34,
treatment ниже control), хотя вероятность конверсии treatment была
задана выше (0.115 против 0.10) — направление в тексте вопроса
подразумевало положительный, но не гарантированный эффект.
**Почему выглядит правильно:** при малой выборке (n=200) случайный шум
вполне законно разворачивает знак разницы. Программной ошибки тут нет.
**Почему неправильно:** датасет остался технически верным (иллюстрирует
низкую мощность так же исправно), но противоречил интуитивному
прочтению вопроса «treatment лучше, но недостаточно значимо» — при
отрицательном знаке первое чтение сбивает с толку.
**Как правильно:** для датасетов, привязанных к конкретному
направлению эффекта в тексте вопроса, подбирать зерно генератора так,
чтобы знак совпадал с заявленным в вопросе — та же практика, что в
`step-03.md`.

**Ошибка:** C28 в первой версии считала z через `random`-симуляцию при
n=50000, где случайный шум одной симуляции (около ±0.3 п.п.) был
сравним с самим эффектом (0.2 п.п.) — прогон то показывал значимость,
то нет, в зависимости от зерна.
**Почему выглядит правильно:** симуляция на слух «честнее», чем прямая
подстановка вероятностей.
**Почему неправильно:** цель ловушки — показать, что фиксированный
маленький эффект становится значимым при большом n; для этого нужны
точные, а не шумно оценённые доли — при n=50000 шум одной симуляции
конкурирует с самим демонстрируемым эффектом и результат неустойчив от
прогона к прогону.
**Как правильно:** там, где демонстрируется свойство самого порога (не
поведение случайной величины), считать по точным входным долям
напрямую, без слоя случайной симуляции поверх них.

## 1.8. Вопрос уровня собеседования

**Вопрос:** «Перед тем как анализировать результаты A/B-теста, какие
три проверки вы сделаете, не глядя ещё на саму метрику успеха?»

**Эталон (ответ покрывает ≥3 из 4 пунктов):**
1. Sample Ratio Mismatch — фактическое разбиение трафика соответствует
   заданному.
2. Баланс групп до старта теста по ключевым метрикам (нет ли разницы
   ещё до вмешательства).
3. Отсутствие интерференции между группами (общий инвентарь, общий
   граф пользователей, общая система рекомендаций).
4. Совпадение периода теста с внешними событиями, которые могут
   исказить перенос результата на обычное время.
