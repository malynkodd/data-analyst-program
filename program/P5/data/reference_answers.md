# Эталонные ответы P5 («Портфель просрочки»)

Считает `reference_p5.py`, независимо от `generate_p5.py`. Прогон на
машине автора 2026-08-22.

## Контрольная точка

```
> python program\P5\data\generate_p5.py
```

Ожидается:

```
applications.csv:      7288 строк
loans.csv:              4917 строк
schedule.csv:          14751 строк
payments.csv:          14751 строк
marketing_spend.csv:       1 строка
```

Точные sha256 — вывод генератора на конкретной машине (зависит только
от `SEED = 20260822`, не от машины). Эталон структуры — `ref_*.csv` в
этой папке.

## Определения (решение 30) — что значит каждое число

- **dpd_strict** — для каждого платежа по графику: если оплачен,
  `(факт.дата платежа − дата по графику).days`; если не оплачен на дату
  выгрузки — `(CUTOFF − дата по графику).days`. График (`schedule.csv`)
  неизменен: пролонгация (`payments.csv`, `extended`) не двигает эту
  величину — это осознанный выбор, обоснование ниже (критерий 6).
- **CUTOFF** = 2026-07-01 (дата выгрузки). **SCORE_CHANGE** = 2026-04-01
  (скоринг ужесточён ровно за три месяца до CUTOFF).
- **«Зрелый» для FPD** — `due_date` первого платежа ≤ CUTOFF
  (`origination_date ≤ 2026-06-01`).
- **«Зрелый» для FPD30** — `due_date` первого платежа + 30 дней ≤ CUTOFF
  (`origination_date ≤ 2026-05-02`) — нужно 30 дней сверх даты платежа,
  чтобы знать, перешла ли просрочка порог.
- **«Зрелый» для roll rate / винтажа / ever_90dpd** — `due_date`
  **третьего** (последнего) платежа + 90 дней ≤ CUTOFF
  (`origination_date ≤ 2026-01-02`). Это единственная линия, отделяющая
  «можно ответить» от «нельзя» в этом проекте.

## Критерий 1 — approval_rate

```
approval_rate: 0.7088 (5166/7288)
```

База — все заявки за 18 месяцев (2025-01-01…2026-06-30), ключ —
`approved == True`. Порог одобрения сам по себе разный до/после
2026-04-01 (580 → 620 по построению) — approval_rate здесь общий за весь
период, не сравнение до/после (это делает `ref_default_comparison.csv`,
не эта метрика).

## Критерий 1 — avg_ticket (средний чек)

```
avg_ticket: 10186.03 грн (4917 займов)
```

База — все выданные займы (не заявки), ключ — `principal`, простое
среднее.

## Критерий 1 — fpd / fpd30

```
fpd:   0.2748 (n=4679 зрелых по первому платежу)
fpd30: 0.0994 (n=4446 зрелых по first-payment+30д)
```

fpd — доля первых платежей с `dpd_strict > 0` (любая просрочка) среди
зрелых по первому платежу. fpd30 — доля с `dpd_strict >= 30` среди
зрелых по first-payment+30д. fpd ≠ fpd30 — разные пороги, разные базы
(4679 против 4446), не должны совпасть.

## Критерий 1 — roll_rate_30_60

```
roll_rate_30_60: 0.7197 (611/849), зрелых для 90dpd — 3431 займов
```

База — займы, «зрелые для 90dpd» (см. выше), у которых `worst_dpd`
(максимум `dpd_strict` по трём платежам) уже пересёк 30 (849 займов —
это `n` из `ref_funnel_metrics.csv`). Ключ — доля из них, чей
`worst_dpd` пересёк ещё и 60 (611). **Сравнение с ошибочной
интерпретацией** — доля 60+ dpd среди ВСЕХ 3431 зрелых займов (не
только тех, кто уже был в 30-корзине): `611/3431 = 0.1781` — в 4 раза
меньше 0.7197, тот же приём, что в M11 (`step-01.md`, критерий готовности).

## Критерий 9 — vintage (`ref_vintage.csv`, 12 строк, 2025-01…2025-12)

Когорта — месяц `origination_date`, не месяц платежа. Доля —
`ever_60 = worst_dpd >= 60`, среди зрелых для 90dpd займов этой когорты.
Диапазон 14.9%–20.8%, без выравнивания. **Все 12 строк — только 2025
год: ни одна когорта после смены скоринга (2026-04-01) не зрелая для
этой метрики** — прямое следствие того, что зрелость требует
`origination_date ≤ 2026-01-02`, а смена была на три месяца позже.

## Критерий 1 — repeat_customer_rate

```
repeat_customer_rate: 0.0957 (426/4453)
```

База — уникальные заявители хотя бы с одним займом (`nunique`, 4453),
не число займов. Ключ — доля тех, у кого займов больше одного (426).

## Критерий 1 — cac_per_loan

```
cac_per_loan: 73.60 грн (бюджет 361884.40 / 4917 займов)
```

Портфельная метрика (один общий бюджет периода, как в M11), делитель —
число ВЫДАННЫХ займов, не заявок и не одобренных заявок.

## Критерии 3–5 — главный вопрос проекта: стало ли лучше после смены скоринга

`ref_default_comparison.csv`:

| Определение | Период | Значение | n |
|---|---|---|---|
| fpd30 (быстрый сигнал, зрелость +60 дней) | до 2026-04-01 | 0.1009 | 4230 |
| fpd30 | с 2026-04-01 | 0.0694 | 216 |
| ever_90dpd (полный горизонт, зрелость +180 дней) | до 2026-04-01 | 0.1242 | 3431 |
| ever_90dpd | с 2026-04-01 | **нет данных** | 0 |

**На fpd30 ужесточение выглядит успешным** — 10.1% → 6.9%, но на
`n=216` (одна зрелая когорта, апрель 2026 частично май). **На
ever_90dpd ответить нельзя вообще** — ни одного займа, выданного после
смены скоринга, ещё не прошёл полные 180 дней зрелости на дату
выгрузки (CUTOFF 2026-07-01). Это не пробел данных, который можно
закрыть точнее посчитав, — это свойство времени: горизонт наблюдения
физически не наступил (критерий 5).

## Критерий 7 — конфаундер: смена канала совпала со сменой скоринга

Доля `affiliate` (канал с более рискованным пулом заявителей, средний
`true_score` 600 против 655 у `partner_app`) в заявках: до 2026-04-01 —
приблизительно 55–60%, после — приблизительно 25–30% (линейный переход
±45 дней вокруг 2026-04-01, `generate_p5.py`, `channel_shares()`).
Улучшение fpd30 после смены скоринга (0.1009 → 0.0694) могло бы
получиться и при неизменном пороге одобрения, только за счёт того, что
после апреля заявители в среднем более качественные — оба эффекта
меняются в одном направлении в одно и то же время, и это проектное
датасета свойство, не находка задним числом.

## Критерий 6 — пролонгации: выбранная трактовка

Отчётные числа выше посчитаны от **исходной** даты по графику
(`dpd_strict`, пролонгация не двигает эту величину) — обоснование:
пролонгация в этом проекте — мера снисхождения кредитора, а не
пересмотр факта, что заёмщик не заплатил в срок; для риск-отчётности
(в отличие от бухгалтерского учёта операций) исходная дата — то, что
защищает от «просрочка исчезает, если её продлить». Альтернатива —
считать от `extended_due_date`, если она есть (`payments.csv`,
столбец) — даёт систематически более низкие dpd для продлённых
платежей; не выбрана эталоном, но вычислима тем же `payments.csv`, если
проверяющему нужно показать обе трактовки.
