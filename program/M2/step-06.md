# M2.6. Обрабатывает ошибки поиска через ЕНД/ЕСЛИОШИБКА вместо игнорирования #N/A

Умение: D2 (задачи 7–8 из 10: обработка ошибок; задачи 1–3 — XLOOKUP/
ИНДЕКС+ПОИСКПОЗ, `step-04.md`; задачи 4–6 — СУММЕСЛИМН, `step-05.md`;
задачи 9–10 — текстовые функции, `step-07.md`)
Модуль: M2
Требуется до этого: `step-04.md` (нужен рабочий `XLOOKUP`/`MATCH` по
`product_lookup.csv` — этот шаг не ищет по-новому, а обрабатывает случаи,
когда поиск из `step-04.md` не находит совпадения)
Время: 2.5–3.5 ч (оценка проектная, не измерена; калибровка —
`research/self.md`)

## 1.1. Цель и связь с умением

После шага вы явно обрабатываете случаи, когда `XLOOKUP`/`MATCH` не
находит `product_id` в справочнике (838 из 20 000 строк,
`data/README.md`), — вместо того, чтобы оставить `#N/A` в таблице или
скрыть его случайно подобранной формулой. Это задачи 7–8 из 10 формул D2.

## 1.2. Теория своими словами

`XLOOKUP` и `MATCH` из `step-04.md` возвращают ошибку `#N/A`, если
искомое значение не найдено ни разу в диапазоне поиска — это не сбой
формулы, а корректный сигнал «совпадения нет». Две функции обрабатывают
такой сигнал по-разному:

- **`IFERROR(формула, значение_при_ошибке)`** — подменяет **любую**
  ошибку (`#N/A`, `#VALUE!`, `#REF!`, `#DIV/0!` и другие) на указанное
  значение.
- **`IFNA(формула, значение_при_НД)`** — подменяет **только** `#N/A`;
  любая другая ошибка (например, `#VALUE!` из-за опечатки в имени листа)
  проходит насквозь и остаётся видимой.

Для обработки «товар снят с продажи, справочник не знает такого
`product_id`» правильный выбор — `IFNA`, а не `IFERROR`: отсутствие
совпадения (`#N/A`) здесь ожидаемо и предусмотрено (838 строк из 20 000
по конструкции датасета, `data/README.md`), а `#VALUE!`/`#REF!` были бы
признаком настоящей ошибки в самой формуле (опечатка в адресе листа,
сдвинутый диапазон) — такую ошибку `IFERROR` спрятал бы точно так же, как
и ожидаемое отсутствие совпадения, и вы бы не узнали о поломке формулы,
пока кто-то не заметил неправдоподобные числа.

Для подсчёта, сколько строк не нашли совпадения, — не формула на каждую
строку, а один агрегат сразу по всему диапазону:

```
=SUMPRODUCT(--ISNA(MATCH(product_id_range, product_lookup!A:A, 0)))
```

`MATCH(диапазон, ...)` в этой форме возвращает **массив** результатов
поиска — по одному на каждую строку диапазона, а не один результат.
`ISNA(...)` превращает каждый элемент массива в `ИСТИНА`/`ЛОЖЬ`; двойной
минус (`--`) переводит `ИСТИНА`/`ЛОЖЬ` в `1`/`0`; `SUMPRODUCT` складывает
весь массив. Результат — число строк, где совпадения не было, без
отдельной вспомогательной колонки на 20 000 строк.


**Справочник по функциям этого шага.** Формулы здесь даны английскими
именами; в русской и украинской локализации имена другие, логика та же.
Полный список аргументов — в справочнике Microsoft, а не в этом тексте:

- [`IFERROR`](https://support.microsoft.com/en-us/office/iferror-function-c526fd07-caeb-47b8-8bb6-63f3e417f611)
- [`XLOOKUP`, аргумент `if_not_found`](https://support.microsoft.com/en-us/office/xlookup-function-b7fd680e-6d10-43e6-84f9-88eae8bf5929)

## 1.3. Разобранный пример на сквозном датасете

**Задача 7 — `IFNA` на конкретной строке.**

Заказ `S00002` ссылается на `product_id = P062`, которого нет в
`product_lookup.csv` (`data/reference_answers.md`, «Точечные проверки»):

```
=IFNA(XLOOKUP("P062", product_lookup!A:A, product_lookup!B:B), "немає в довіднику")
→ немає в довіднику
```

Для сравнения — заказ `S00001` (`product_id = P039`, есть в справочнике)
та же формула не меняет результат:

```
=IFNA(XLOOKUP("P039", product_lookup!A:A, product_lookup!B:B), "немає в довіднику")
→ appliances-039
```

`IFNA` вмешивается только там, где действительно `#N/A`, — найденные
значения проходят как есть.

**Задача 8 — агрегатный счётчик.**

```
=SUMPRODUCT(--ISNA(MATCH(product_id_range, product_lookup!A:A, 0)))
→ 838
```

(`data/reference_answers.md`, «Счётчики дефектов» — 838 из 20 000,
4.19%).

## 1.6. Типичные ошибки

**Ошибка:** использует `IFERROR` вместо `IFNA` для обработки отсутствия
товара в справочнике.
**Почему выглядит правильно:** результат для `S00002`/`S00037` — тот же
текст-заглушка, разницы не видно на этих конкретных строках.
**Почему неправильно:** `IFERROR` скрывает и `#N/A` (ожидаемое отсутствие
товара), и `#VALUE!`/`#REF!` (настоящую поломку формулы — например, если
кто-то случайно переименовал лист `product_lookup` или сдвинул диапазон).
Обе ситуации в этом случае выглядят одинаково — текст-заглушка — и
отличить «838 товаров реально сняты с продажи» от «формула сломана у всех
строк» становится невозможно, глядя только на результат.
**Как правильно:** `IFNA` для ожидаемого отсутствия совпадения; `IFERROR`
— только там, где действительно нужно перехватывать любые ошибки, а не
по умолчанию.

**Ошибка:** в формуле `SUMPRODUCT` для задачи с каналом использует
`MATCH` не по всему диапазону, а поэлементно в отдельной вспомогательной
колонке, потом дополнительно фильтрует по каналу вручную — считая, что
`SUMPRODUCT` с несколькими массивами не поддерживает такое условие.
**Почему выглядит правильно:** промежуточная колонка даёт тот же
результат — 388 при правильной ручной фильтрации.
**Почему неправильно:** это не ошибка вычисления, а лишний шаг: задание
именно проверяет, что `SUMPRODUCT` умеет перемножать несколько
массивов-условий в одной формуле (`--ISNA(...)`, умноженное на `--(диапазон_канала="online")`),
без отдельной вспомогательной колонки — тот же принцип, что несколько
условий в `SUMIFS` (`step-05.md`), только внутри `SUMPRODUCT`. Если
получить те же 388 через ручной фильтр и подсчёт — число совпадёт, но
навык, который проверяет этот шаг, не будет продемонстрирован.
**Как правильно:** `=SUMPRODUCT(--ISNA(MATCH(product_id_range,
product_lookup!A:A,0)), --(channel_range="online"))` — оба условия в
одной формуле.

**Ошибка:** текст-заглушка внутри `IFNA` — само слово `"#N/A"` в виде
текста (например, `IFNA(XLOOKUP(...), "#N/A")`).
**Почему выглядит правильно:** формула технически работает, ошибка
перехвачена, ничего не падает.
**Почему неправильно:** результат в ячейке — строка `"#N/A"`, неотличимая
на глаз от настоящей ошибки `#N/A`, но не являющаяся ошибкой: `ISNA()` на
такой ячейке вернёт `ЛОЖЬ` (это текст, не ошибка), и если кто-то потом
считает `SUMPRODUCT(--ISNA(...))` по этой колонке заново, результат будет
0 вместо реального числа отсутствующих совпадений — подмена ошибки на
текст, похожий на ошибку, ломает дальнейшую агрегацию.
**Как правильно:** текст-заглушка должен явно отличаться от вида ошибки —
например, `"немає в довіднику"`, а не `"#N/A"` или `"N/A"`.

## 1.8. Вопрос уровня собеседования

**Вопрос:** «Ваша формула `ВПР`/`XLOOKUP` иногда возвращает `#N/A`. Вы
обернули её в `IFERROR` и заменили на пустую строку — коллега говорит,
что это плохая практика. Почему он может быть прав?»

**Эталон (ответ покрывает ≥3 из 4 пунктов):**
1. `IFERROR` скрывает любую ошибку, не только «значение не найдено» —
   в том числе те, что говорят о реальной поломке формулы.
2. Замена на пустую строку неотличима от «искали и не нашли ничего» и от
   «формула сломалась и результат — не число», обе ситуации выглядят
   одинаково пусто.
3. Предлагает `IFNA` вместо `IFERROR`, если ошибка ожидаемо только
   `#N/A`.
4. Предлагает текст-заглушку, явно говорящий о причине («не найдено в
   справочнике»), а не пустую строку — чтобы разница между «пусто, потому
   что не нашли» и «пусто, потому что и не искали» не терялась.
