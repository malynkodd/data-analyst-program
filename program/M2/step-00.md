# M2.00. Декларация модуля (умения, датасет, шаги)

Не шаг для учащегося — служебный файл, требуемый разделом 1.3 скилла
curriculum-design: датасет и состав модуля объявляются один раз, целиком,
до первого содержательного шага (правило вводилось при ревью пилота M1/M3
именно затем, чтобы не расширять схему задним числом на длинном модуле —
M2 является первой проверкой этого правила на модуле из девяти шагов).

## Умения модуля и их шаги

Модуль M2 закрывает D1, D2, D3, D4 (часть 2.1 blueprint), 35–46 ч.

| Умение | Часть умения | Шаг | Часы |

| D1 | Очистка дат и текстовых чисел (`amount_raw`) на полной выгрузке | `step-01.md` | 5.0–6.5 |
| D1 | Очистка категорий (регистр/пробелы) и возвратов (отрицательные суммы в той же колонке) | `step-02.md` | 4.5–6.0 |
| D1 | Итоговая проверка: с нуля, за 90 минут, сводная с 3 срезами, сходится с SQL-эталоном | `step-03.md` | 5.5–7.0 |
| D2 | XLOOKUP / ИНДЕКС+ПОИСКПОЗ (задачи 1–3 из 10), закрепление диапазонов `$A$1` | `step-04.md` | 4.5–5.5 |
| D2 | СУММЕСЛИМН (задачи 4–6 из 10) | `step-05.md` | 3.0–4.0 |
| D2 | Обработка ошибок ЕСЛИОШИБКА/ЕНД (задачи 7–8 из 10) | `step-06.md` | 2.5–3.5 |

Сумма: 35.0–46.0 ч при вилке части 6.1 blueprint 35–46 ч.

**Оценка сведена к вилке, не измерена** (решение 24
`design/decisions.md`). Совпадение по обеим границам на девяти шагах —
признак подгонки суммы под заранее известное число, а не подтверждение
оценок; `check_module_hours()` в `tools/check_consistency.py` печатает на
этот случай `[WARN]`.

Строка M2 в части 6.1 помечена «Не требуется: совпадает с [М], разброс
33%» — то есть у вилки есть внешний ориентир, чего нет у M1. Но
фактического замера прохождения за ней всё равно нет, и подведённая под
неё сумма девяти шагов ориентиром не становится. Часы не переоцениваются
задним числом; разрешит вопрос `research/self.md`, на 2026-07-31 пустой.

D1 разбит на 3 шага по той же логике, что A5 в M1 (часть скилла: шаг
может закрывать умение частично, если следующий шаг того же модуля
закрывает остаток) — очистка дат/чисел, затем очистка категорий/возвратов,
затем интегрированная проверка «с нуля за 90 минут» с готовым, уже
очищенным материалом из первых двух шагов. D2 разбит на 4 шага по группам
формул, с итоговой проверкой всех 10 задач в последнем. D3 и D4 — по
одному шагу каждое: `step-08.md` (письменное обоснование выбора
инструмента) и `step-09.md` (выбор формы диаграммы под тип вопроса,
дописан решением 41).

## Датасет модуля — объявлен целиком

**Категория (часть 1.3 curriculum-design):** синтетика для модуля,
ведущего к проекту — M2 → P1 (часть 3.1 blueprint, «P1 ← M2,M3»).
Генератор и спецификация встроенных дефектов лежат в репозитории, эталон
известен точно. Это не тот же датасет, что будет у самого проекта P1
(«сеть из 12 магазинов») — тот пишется отдельно при авторинге P1; учебный
датасет модуля и датасет конкретного проекта — разные артефакты.

**Файлы:** `program/M2/data/` — полное описание в `data/README.md`.
Сводка:

| Файл | Роль |
|---|---|
| `generate_sales_extract.py` | Генератор, детерминирован (`SEED = 20260802`) |
| `sales_extract_raw.csv` | 20 000 строк — «грязная» выгрузка продаж, эталон для D1 |
| `product_lookup.csv` | 60 товаров (`P001`–`P060`) — справочник для D2 |
| `build_reference.py` | SQL-эталон (sqlite): применяет правила очистки из шагов, печатает контрольные суммы |
| `reference_answers.md` | Предвычисленные контрольные числа — источник всех чисел в шагах |

### Схема `sales_extract_raw.csv` (8 колонок, фиксирована на весь модуль)

| Колонка | Роль | Дефект |
|---|---|---|
| `order_id` | `S00001`…`S20000` | нет |
| `order_date_raw` | дата заказа | два формата: ISO и `ДД.ММ.ГГГГ`, разделители не пересекаются (`-` против `.`) |
| `category_raw` | категория товара | 5 канонических категорий, каждая в 5 вариантах регистра/пробелов |
| `product_id` | ссылка на `product_lookup.csv` | 4.19% строк (838 из 20 000) ссылаются на товар, снятый с продажи — отсутствует в справочнике |
| `channel` | `online`/`retail`/`wholesale` | чистое поле — второй срез D1 (первый — категория, третий — квартал) |
| `quantity` | целое 1–5 | чистое поле |
| `unit_price` | цена за единицу | чистое поле — контрольная величина, не то же самое, что очищенный `amount` (см. `reference_answers.md`, «наивный пересчёт») |
| `amount_raw` | сумма заказа | текст, 4 формата (точка / запятая-десятичная / пробел-тысячи / суффикс «грн»); возвраты — отрицательные суммы в той же колонке, часть — в форме `(1234.56)` вместо `-1234.56` |

### Схема `product_lookup.csv` (4 колонки)

| Колонка | Роль |
|---|---|
| `product_id` | `P001`–`P060` |
| `product_name` | `<код категории>-<номер>`, например `laptops-021` |
| `category` | канонический кириллический текст, без дефектов |
| `unit_cost` | себестоимость единицы |

### Контрольные числа (полный список — `data/reference_answers.md`)

- `grand_total_amount` (вся таблица, после очистки) = **530 839 498.36**.
- Сумма по 3 срезам одновременно (эталон `step-03.md`): категория
  `laptops`, квартал `2025-Q2`, канал `online` → **12 513 158.75**, 212
  строк.
- Возвратов — 952 строки (507 в скобках, 445 с минусом); строк с
  отсутствующим в справочнике `product_id` — 838 (4.19%).
- Наивный пересчёт `quantity*unit_price` отличается от очищенной суммы
  на 59 858 185.36 — ровно удвоенная сумма модулей всех возвратов.

Датасет не меняется между `step-01.md`–`step-09.md`. Шаги D1
(`step-01.md`, `step-02.md`) строят очищенные колонки-помощники
(`category_clean`, `order_date_clean`, `quarter`, `amount_clean`) поверх
сырых — начиная со `step-04.md` (D2) шаги используют уже очищенные
колонки, а не сырые, то есть очистка данных делается один раз в модуле, а
не в каждом шаге заново.

## Зависимости модуля

Часть 3.1/3.2 blueprint: M2 → M3 (жёсткая) — таблицы дают первое понятие
о «строке/колонке/агрегате» до синтаксиса SQL. M0 → M2 (жёсткая, через
общее правило части 3.2: любой шаг с терминалом/скриптами требует I2 из
M0) — `build_reference.py` запускается тем же способом, что скрипты M0 и
M1. M2 → P1 (часть 3.1: «P1 ← M2,M3») — не жёсткая зависимость шагов
модуля друг от друга, а связь с портфолио: P1 пишется отдельно, после
прохождения и M2, и M3.
