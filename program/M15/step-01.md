# M15.01. Ставит Tableau Public и подключает пять таблиц датасета M4

Умение: — (инфраструктура). Шаг ставит инструмент и переносит данные;
ни одного из 30 умений части 1 blueprint не закрывает (решение 23).
Умение C3 начинается со `step-02.md`
Модуль: M15
Требуется до этого: M4 закрыт целиком (пять таблиц, пять связей, шесть
мер — предмет переноса)
Новые файлы, объявляемые этим шагом: `program\M15\work\connection_check.csv`
Время: 4–5 ч

## 1.1. Цель и связь с умением

После шага в Tableau Public подключены пять CSV датасета M4 и построены
те же пять связей, что в `M4/step-03.md`. Это предусловие C3: перенос
дашборда нельзя засекать секундомером (критерий «≤6 ч»), пока источник
данных не готов, — иначе время подключения смешается со временем
собственно переноса.

## 1.2. Теория своими словами

**Tableau Public — не то же самое, что Tableau Desktop.** Официальный
FAQ: «Tableau Public is a free platform to explore, create, and share
data visualizations using publicly available data online»
([FAQ](https://help.tableau.com/current/pro/desktop/en-us/public_faq.htm)).
Два следствия важны для этого шага:

- **Данные становятся публичными.** «As soon as a workbook is published
  to Tableau Public, the viz is accessible by anyone on the internet» —
  и это не проблема для датасета M4: он синтетический (решение 29,
  `design/decisions.md`), реальных людей и реальных платежей в нём нет.
  Если бы модуль переносил проект P3/P4/P6 (реальные данные), этот шаг
  был бы недопустим без отдельной проверки, что публикуемые данные
  анонимны.
- **Только выгрузки (extract), не живое соединение.** «Cannot save
  workbooks with live connections (extracts only)» — при публикации
  Tableau «creates an extract of the data connection»
  ([сохранение в Tableau Public](https://help.tableau.com/current/pro/desktop/en-us/publish_workbooks_tableaupublic.htm)).
  Числа фиксируются на момент публикации, как и у Power BI (M4 тоже не
  строил живое соединение к CSV — «Закрыть и применить» делает то же
  самое: снимок).

**Подключение к текстовому файлу.** Документация
([Text File](https://help.tableau.com/current/pro/desktop/en-us/examples_text.htm)):
«After you open Tableau, under Connect, click Text File. Select the file
you want to connect to, and then click Open»; «Tableau connects to
delimited text files (\*.txt, \*.csv, \*.tab, \*.tsv)». Первая строка
файла читается как заголовок по умолчанию: «select whether the first row
contains column names. This option is selected by default».

**Связи между таблицами — «noodles», не JOIN.** Документация
([Relate Your Data](https://help.tableau.com/current/pro/desktop/en-us/relate_tables.htm)):
«Drag a table to the canvas» (первая, базовая), затем «Drag another
table to the canvas. When you see the "noodle" between the two tables
that you want to relate, drop that table» — на холсте появляется линия
между таблицами, а не объединённая таблица, тот же смысл, что у связей
Power BI (данные не сливаются физически, схема остаётся звездой).
«Tableau automatically attempts to create the relationship based on
existing key constraints and matching fields» — то же автоопределение по
совпадению имён колонок, что в M4 (`step-03.md`, 1.2), и та же
осторожность нужна: подставленное совпадение не значит, что пара полей
осмысленна (Tableau, как и Power BI, не проверяет пересечение значений,
только структуру).

**Если совпадений нет, связь по умолчанию — «многие ко многим».**
«If no constraints are detected, a Many-to-many relationship is created
and referential integrity is set to Some records match» — раскладка
пяти связей M4 напрямую переносится сюда: три связи (`mcc` → `code`,
`tx_date`/`settled_date` → `date_key`) не совпадают по имени и требуют
ручной правки пары полей («Select a field pair, and then select from the
list of fields below to set a new pair of matching fields»); связь по
`plan_key` совпадает по имени в обеих таблицах, как в M4 (R21,
`research/tools-gate.md`) — стоит проверить, не подставилась ли она уже
сама.

## 1.3. Разобранный пример — пять связей

| Связь | Таблицы | Поля | Как в M4 |
|---|---|---|---|
| 1 | `transactions` — `merchants` | `merchant_id` = `merchant_id` | автоопределение (имена совпадают) |
| 2 | `transactions` — `mcc_categories` | `mcc` = `code` | ручная правка пары (имена разные) |
| 3 | `transactions` — `calendar` | `tx_date` = `date_key` | ручная правка пары |
| 4 | `transactions` — `calendar` | `settled_date` = `date_key` | ручная правка пары; вторая связь к той же таблице |
| 5 | `transactions` — `merchant_plan` | `plan_key` = `plan_key` | вычисляемое поле, см. ниже |

**`plan_key` — вычисляемое поле, не колонка файла**, тот же составной
ключ, что в M4 (`step-03.md`, 1.3): `merchant_id` (или `merchant_ref`) и
`period_ym` не уникальны по отдельности. В Tableau вычисляемое поле
создаётся правым щелчком по источнику данных → **Создать вычисляемое
поле**, формула:

```
STR([merchant_id]) + "|" + [period_ym]
```

— то же самое выражение, что M-код M4 (`Text.From([merchant_id]) & "|" &
[period_ym]`), на другом синтаксисе. Поле заводится в обеих таблицах —
`transactions` (от `merchant_id`) и `merchant_plan` (от `merchant_ref`)
— до того, как строится связь 5.

**У M15, в отличие от M4, нет отдельного файла-проекта, который можно
прочитать текстом** (Tableau Public хранит `.twbx` — архив, не текстовый
формат TMDL) — проверка этого шага поэтому не читает файл проекта, а
сверяет числа, которые учащийся видит на простом визуале после того,
как все пять связей построены.

## 1.4. Задание

1. Установите [Tableau Public Desktop](https://help.tableau.com/current/pro/desktop/en-us/public_faq.htm)
   (бесплатно).
2. Подключите файл `program\M4\data\csv\transactions.csv`: **Connect →
   Text File**, откройте файл, оставьте «первая строка — заголовки»
   (значение по умолчанию).
3. Перетащите на холст оставшиеся четыре таблицы по очереди
   (`merchants.csv`, `mcc_categories.csv`, `merchant_plan.csv`,
   `calendar.csv`) и постройте пять связей из 1.3 — для связи 5 сначала
   заведите вычисляемое поле `plan_key` в обеих таблицах.
4. Постройте простой лист (Worksheet): перетащите `amount_uah` на
   **Text** (сумма по умолчанию), `tx_id` — тоже на полку с изменением
   агрегата на **Count** (не Count Distinct — это тот же счётчик, что
   `COUNTROWS` в M4).
5. Запишите оба числа в `program\M15\work\connection_check.csv`:

   ```
   Total Amount,Tx Count
   <ваша сумма>,<ваш счётчик>
   ```

6. Проверьте:

   ```
   > python program\M15\data\check_connection.py
   ```

## 1.5. Критерий готовности

Проверяет `check_connection.py`. Порог — **две строки `[OK]`, код
возврата 0**:

| Проверка | Что доказывает |
|---|---|
| строк в `transactions` (через `Tx Count`) | связь 5 не размножила строки декартовым произведением — типовой отказ составного ключа, тот же класс, что R21 в M4 |
| сумма `amount_uah` | таблица фактов подключена и не искажена связями (искажённая связь дала бы сумму, отличную от исходного файла) |

Эталон — не файл в репозитории, а сам исходный `transactions.csv`,
пересчитанный скриптом заново при каждом запуске: расхождение здесь
означает ошибку в связях этого шага, а не устаревший эталон.

## 1.6. Типичные ошибки

**Ошибка:** связывает `transactions` и `merchant_plan` по `merchant_id`
= `merchant_ref` напрямую, без `plan_key`.
**Почему выглядит правильно:** оба поля про мерчанта, Tableau предложит
связь по совпадению смысла полей, и лист построится без ошибок.
**Почему неправильно:** тариф в датасете помесячный (M4, `step-03.md`,
1.6) — тот же дефект, что и в Power BI: комиссия по неверному ключу
даёт число, близкое к правильному, но не совпадающее (169159.15 против
169676.11, измерено в M4).
**Как правильно:** вычисляемое поле `plan_key` в обеих таблицах,
связь — по нему.

**Ошибка:** после подключения `merchant_plan` число в `Tx Count`
увеличивается (например, до 13164 — ровно вдвое).
**Почему выглядит правильно:** связь построена, лист не выдаёт ошибки,
цвет не красный.
**Почему неправильно:** связь по несоставному ключу или без ключа
вообще даёт «многие ко многим» по умолчанию — каждая строка
`transactions` сопоставляется более чем с одной строкой `merchant_plan`
(несколько периодов одного мерчанта), и счётчик строк размножается.
**Как правильно:** `check_connection.py` ловит это первой же проверкой
(«строк в transactions») — расхождение с исходным файлом сигнализирует
о связи раньше, чем это всплывёт в мерах `step-02.md`.

## 1.7. Честная оценка времени

4–5 ч. Оценка проектная, не измерена (структурное ограничение — нет
доступа к Tableau Public, 1.1 `step-00.md`). Из чего складывается:
установка — минуты; первое подключение и знакомство с интерфейсом связей
(«noodles») — час; пять связей с разбором несовпадающих имён — 1,5–2 ч.
Время этого шага **не входит** в ≤6-часовой порог критерия C3 —
он считается отдельно, только в `step-02.md`.

## 1.8. Вопрос уровня собеседования

**Вопрос:** «Вы подключили пять таблиц в BI-инструменте, визуал строится,
но сумма по факту вдвое больше ожидаемой. С чего начнёте?»

**Эталон (ответ покрывает ≥2 из 3 пунктов):**
1. Проверяет число строк таблицы фактов до и после добавления связей —
   рост числа строк указывает на связь «многие ко многим» вместо
   «многие к одному».
2. Называет типовую причину: связь построена по полю, не уникальному на
   стороне «один» (например, дате без учёта версии/периода записи).
3. Предлагает способ починки: составной ключ, собранный вычисляемым
   полем, если единственного уникального поля нет.
