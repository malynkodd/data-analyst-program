# Эталонные ответы модуля M4

Все числа получены прогоном на референсной машине автора 2026-07-31:
`generate_m4.py` и `reference_m4.py`, Python 3.11.9, Windows 11. Ни одно
не взято из документации и ни одно не оценено. Маркер «Эталон:» здесь не
используется намеренно: механизм `check_reference_csv_state()` собирает
состояние базы из `.sql`-файлов, а эталоны M4 считаются Python по CSV, и
базы у модуля нет.

**Календарь длиннее периода операций на неделю, и это не описка.**
`tx_date` кончается 2026-06-30 в `csv/` и 2026-07-31 в `csv_next/`, а
`settled_date` переступает эту границу: сдвиг +1…3 дня плюс перенос с
выходных на понедельник даёт до +5 календарных дней. Поэтому календарь
доведён до 2026-07-07 и 2026-08-07 соответственно — 553 и 584 дня.
Обрезанный по границе операций календарь ронял 30 операций на 47482.23
(и 50 на 41581.44 в `csv_next/`) в строку с пустым измерением при разрезе
по дате расчёта — дефект D1, `research/tools-gate.md`, 3.8. Инвариант
`max(settled_date) <= max(date_key)` проверяется и генератором, и
`tools/check_consistency.py`.

**Sha256 считается по всему файлу, а не по первым N строкам.** Объём
датасета генератором не параметризуется: период задан константами
`BASE_START`, `BASE_END`, `NEXT_END`, аргументов командной строки у
скрипта нет. Оговорка M3 про независимость хэша от объёма здесь не нужна
— менять объём нечем, не сменив константу в самом генераторе.

**Детерминированность проверена, а не заявлена:** два запуска подряд дали
побайтово одинаковые файлы (сравнение вывода генератора между прогонами,
расхождений 0).

## Что должно получиться в модели после `step-02.md`

Число строк каждой таблицы **в самом Power BI**, а не в файле. Расхождение
означает, что M-код разобрал файл не так, как разбирает его любой
CSV-парсер.

| Таблица в модели | Строк |
|---|---|
| `transactions` | 6582 |
| `merchants` | 24 |
| `mcc_categories` | 6 |
| `merchant_plan` | 432 |
| `calendar` | 553 |

Отдельно по `merchants`: в файле **27 физических строк** при 24 строках
данных — у двух мерчантов адрес многострочный. Разбор, при котором в
модели оказывается 26 строк вместо 24, — признак `QuoteStyle.None`
(разбор переводов строки внутри значения в кавычках). Число 26, а не 27:
одна из 27 физических строк — заголовок.

Контрольные суммы модели:

- `SUM(amount_uah)` по всем 6582 операциям = **10236902.82**
- то же по `status = 'settled'` (5609 операций) = **8703122.77**
- статусы: `settled` 5609, `declined` 709, `refunded` 264

Обе суммы не считаются вовсе, пока `amount_uah` лежит в модели текстом
(находка P7 гейта: культура `"ru"` подставляется автоматически, и
`1200.0` в ней не число).

## Связи после `step-03.md`

Пять связей. Проверяются по тексту `definition/relationships.tmdl` —
поиском подстроки, а не побайтовым сравнением: имена автосозданных связей
содержат GUID (решение 22, «Проверка через отсутствие строки»).

| # | Из | В | Как создаётся | След в TMDL |
|---|---|---|---|---|
| 1 | `merchants[merchant_id]` | `transactions[merchant_id]` | автоматически при загрузке | имя вида `AutoDetected_<uuid>` |
| 2 | `mcc_categories[code]` | `transactions[mcc]` | вручную | имя без `AutoDetected_` |
| 3 | `calendar[date_key]` | `transactions[tx_date]` | вручную, активна | имя без `AutoDetected_`, строки `isActive:` нет |
| 4 | `calendar[date_key]` | `transactions[settled_date]` | вручную, **неактивна** | `isActive: false` |
| 5 | `merchant_plan[plan_key]` | `transactions[plan_key]` | вручную, по собранному составному ключу | имя без `AutoDetected_` |

Строк `crossFilteringBehavior:`, `fromCardinality:`, `toCardinality:` в
файле быть не должно ни одной: TMDL пишет только отклонения от умолчаний,
а умолчания здесь и есть требуемое — «многие к одному», фильтрация
односторонняя (измерено, `research/tools-gate.md`, 2.9). Строка
`isActive: false` должна встретиться ровно один раз — у связи 4.

## Как сверять экспорт

```
$ python program\M3\data\compare_csv.py <экспорт.csv> program\M4\data\ref_by_category.csv
```

Ожидаемый вывод — `СОВПАДАЕТ: 6 строк, 5 колонок, расхождение 0.`, код
возврата 0. Скрипт сравнивает значения, разобранные по правилам CSV, а не
байты: BOM, кавычки вокруг чисел и десятичную запятую русской локали он
снимает сам (проверено прогоном гейта, 2.7).
