# Сквозной датасет модуля M4 (Power BI)

## Статус этого файла

Полная декларация датасета — `program/M4/step-00.md` (категория датасета,
обоснование отказа от базы M3, три случая связей, требования решения 22).
Этот файл — описание папки `data/` для человека, который её открыл, а не
второй источник истины.

Домен — fintech: платёжный провайдер, эквайринг украинских мерчантов
(решение 21, п. 2). Данные синтетические, генератор детерминирован,
`SEED = 20260731`.

**Сами данные в репозиторий не коммитятся** — решение 22
`design/decisions.md`, раздел «Что коммитится». Папки `csv/` и `csv_next/`
перечислены в корневом `.gitignore`. В git лежат генератор, скрипт
эталонов и три эталонных CSV, каждый из которых — несколько строк.

## Файлы

| Файл | Роль | В git? |
|---|---|---|
| `generate_m4.py` | Генератор датасета. Пишет `csv/` (операции 2025-01-01 … 2026-06-30) и `csv_next/` (тот же набор по 2026-07-31, для C2). Календарь в обеих папках на неделю длиннее периода операций: дата расчёта переступает его границу (D1, `CALENDAR_TAIL_DAYS`). Детерминирован; печатает число строк, sha256 каждого файла и инвариант `max(settled_date) <= max(date_key)`. | да |
| `reference_m4.py` | Считает эталонные значения по `csv/` и пишет три `ref_*.csv`. Источник истины для мер DAX (правило двойного авторства формулы). `Decimal` с `ROUND_HALF_UP`, отдельная проверка на близость к границе округления. | да |
| `check_pbip.py` | Проверяет сохранённый проект `.pbip` по критериям шагов: `--step 01` (три preview-функции), `02` (явный M-код и типы), `03` (связи через отсутствие строк в TMDL), `04` (шесть мер и визуалы). Только читает файлы; Power BI Desktop ему не нужен. | да |
| `reference_answers.md` | Контрольная точка датасета и эталонные числа шагов `step-02.md`–`step-04.md`, все из прогона. | да |
| `ref_by_category.csv` | Эталон визуала 1 (`step-04.md`): категория × `Total Amount`, `Settled Amount`, `Tx Count`, `Decline Rate`. | да |
| `ref_month_ytd.csv` | Эталон визуала 2 (`step-04.md`): год, месяц × `Settled Amount`, `Settled YTD`. | да |
| `ref_plan_commission.csv` | Эталон визуала 3 (`step-04.md`): тариф × `Commission`. | да |
| `csv/` | Пять CSV базового периода: `transactions`, `merchants`, `mcc_categories`, `merchant_plan`, `calendar`. | **нет** — создаётся генератором |
| `csv_next/` | Те же пять файлов, продлённые по 2026-07-31 (календарь — по 2026-08-07), плюс мерчант в новом городе. Для умения C2. | **нет** — создаётся генератором |

Сверка экспорта визуала с эталоном делается `compare_csv.py` из
`program/M3/data/` — тем же скриптом, что и в M3. Второй копии не
заводится: она разошлась бы с первой при следующей правке. Скрипт умеет
десятичную запятую и разделитель разрядов русской локали (находка P9
гейта, `research/tools-gate.md`, 2.7).

## Порядок загрузки

Правило — решение 20 `design/decisions.md`: файл данных появляется в том
шаге, где он нужен впервые, и `step-00.md` этого не дублирует.

| Шаг | Что появляется | Файлы |
|---|---|---|
| `step-01.md` | ничего: устанавливается Power BI Desktop, создаётся пустой проект | — |
| `step-02.md` | все пять таблиц модели сразу | `csv/transactions.csv`, `csv/merchants.csv`, `csv/mcc_categories.csv`, `csv/merchant_plan.csv`, `csv/calendar.csv` |
| `step-03.md` | ничего нового: связи строятся поверх загруженного | — |
| `step-04.md` | ничего нового: меры и визуалы поверх той же модели | — |

Накопительных состояний, как в M3, здесь нет — в Power BI состояние
держит не датасет, а модель поверх него. Таблица оставлена в том же
формате, что у остальных модулей, чтобы правило решения 20 не
приходилось искать заново.

## Как воспроизвести с нуля

```
$ python program\M4\data\generate_m4.py
$ python program\M4\data\reference_m4.py
```

Первая команда пишет `csv/` и `csv_next/` и печатает контрольную точку.
Вторая пересчитывает три `ref_*.csv` и печатает числа, на которые
ссылаются шаги. Обе — стандартная библиотека Python, без `pip install` и
без POSIX-команд (решение 13).
