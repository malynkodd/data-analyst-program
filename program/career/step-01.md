# career.01. Собирает резюме, где каждая строка опирается на файл

Умение: — (карьерный артефакт, вне 46 ID части 1 blueprint; решение 37)
Блок: career («Выход», часть 6.2 blueprint)
Требуется до этого: `step-00.md` этого блока; пройдены P1–P6 — резюме
собирается из их артефактов, а не из списка изученных тем
Новые файлы, объявляемые этим шагом: `program\career\work\cv.md`
Время: 3–4 ч

## 1.1. Цель и связь с умением

После шага существует файл `work\cv.md`, в котором каждое утверждение о
работе названо вместе с числом и путём к файлу, этот факт содержащему.
Собственного ID умения у шага нет: часть 1 blueprint описывает 46 умений
аналитика, а резюме — не умение аналитика, а форма предъявления
результата. Проверяемость от этого не снижается — критерий 1.5
механический.

## 1.2. Теория своими словами

**Резюме без опыта работы состоит из работ, а не из курсов.** При оценке
кандидатов вопрос ставится так: «що саме зробив ТИ» — кандидаты по
умолчанию описывают достижения команды, а не свои
(`research/access.md`, §4, [DOU-расследование](https://dou.ua/lenta/articles/ukrainian-contractors/)).
Там же: курсовые проекты и волонтёрство рекомендуется считать опытом
(Денис Дніпровський, Business Analyst), а портфолио дашбордов с фокусом
на бизнес-задачи «може зіграти вирішальну роль» при найме (Максим
Самсонюк, Head of Analytics, Brainstack).

**Список инструментов пишется по работам, а не наоборот.** Названный
инструмент, за которым не стоит строка с файлом, — это утверждение без
источника. Правило 2 CLAUDE.md запрещает такое в самой программе, и для
резюме исключения нет. Порядок частотности в выборке [М]: SQL
75.6%, Python 52.0%, Power BI 38.2%, Tableau 32.5%, Excel/Sheets 25.2%,
Cloud/DWH 23.6% (`research/market.md`, «Топ-15 навыков»).

**Формулировки без порога.** `понимает`, `знает основы`, `умеет
работать с`, `имеет представление`, `освоил` — их нет ни в одном из 46
умений части 1 blueprint, потому что ни одну нельзя проверить. В резюме
у них та же природа. Отдельно — `ответственный`, `коммуникабельный`,
`стрессоустойчивый`: они не опираются ни на какой файл.

**Уровень английского называется вместе с основанием.** В выборке [М,
§4] 62% вакансий английский не упоминают вовсе, а среди назвавших
уровень с CEFR (n=14) медиана — B2. И строка «английский B2» без
артефакта на английском — ровно то же утверждение без источника.

## 1.3. Разобранный пример: одна строка резюме из одного артефакта

Проект P4 оставил после себя `program\P4\data\ref_match_report.csv`:

```
показатель,значение
уникальных_кодов_контрагентов,361
найдено_в_ЄДР,245
не_найдено,116
```

Плохая строка резюме: «Опыт работы с большими массивами данных,
сопоставление реестров». Проверить нечем: нет числа, нет файла, «большие»
не определено.

Рабочая строка:

```
- Сведение трёх источников по коду ЄДРПОУ, Python и BigQuery: из 361
  уникального кода найдено 245, не найдено 116 —
  `program\P4\data\ref_match_report.csv`
```

Что в ней есть, кроме числа. Решение 30 требует приводить число вместе с
определением, которое его порождает, — база, ключ, пустые, дубли,
сравнение. В одну строку резюме пять определений не помещаются, и
дописывать их туда не нужно: определение живёт в файле, на который строка
ссылается (`program\P4\data\reference_answers.md`, раздел «Определения»),
и открывается за один переход. Строка обязана назвать **ключ** («по коду
ЄДРПОУ») и **базу** («контрагенты контрактов») — остальное вопрос
собеседования, и там оно и всплывёт.

Заполненное целиком резюме на артефактах этого репозитория лежит в
`program\career\data\reference\cv.md`. Оно не образец для копирования:
пути в нём ведут на файлы проектов, а числа — это числа автора.

## 1.4. Задание

Работа идёт в `program\career\work\cv.md`. Скелет — `data\cv_template.md`,
скопировать и заполнить.

1. Пройти по шести проектам P1–P6 и выписать из каждого один результат:
   что было сделано, какое число на выходе, в каком файле оно лежит.
2. Собрать раздел «Работы»: шесть строк, в каждой — глагол действия,
   число, путь к существующему файлу. В каждой строке назвать
   инструмент, которым сделано.
3. Заполнить раздел «Инструменты» — только тем, что названо в «Работах».
   Инструмент без строки в «Работах» вычеркнуть, а не оставить «на
   вырост».
4. Написать раздел «Чем могу быть полезен»: две-три строки. Проверка на
   пригодность одна — каждую строку можно подтвердить пунктом из
   «Работ».
5. Заполнить раздел «Английский»: уровень по CEFR и путь к артефакту на
   английском. Артефакт появится на шаге 02; до него в строке стоит путь
   `program\career\work\summary_en.md`, и до шага 02 проверка на нём не
   сойдётся — это ожидаемо.
6. Заполнить «Контакты».
7. Прогнать проверку и довести до нуля `[FAIL]`.

## 1.5. Критерий готовности

```
python program\career\data\check_cv.py
```

Восемь `[OK]`, ни одного `[FAIL]`, код возврата 0. Что именно
проверяется, с порогами:

| Проверка | Порог | Допуск |
|---|---|---|
| Объём | ≤450 слов | расхождение 0: 451 слово — `[FAIL]` |
| Разделы | все 5 названы | расхождение 0 |
| Строк в «Работах» | ≥6 | по одной на P1–P6 |
| Число в строке | в каждой из строк | расхождение 0 |
| Путь в строке | файл существует на диске | расхождение 0 |
| Инструменты | каждый назван хотя бы в одной строке «Работ» | расхождение 0 |
| Английский | уровень A1..C2 **и** путь к существующему файлу | оба, не один из двух |
| Формулировки без порога | 0 попаданий из 14 форм | расхождение 0 |

Порог 450 слов — не круглое число на глаз: заполненное эталонное резюме
`data\reference\cv.md` даёт 197 слов, шаблон `data\cv_template.md` — 163.
Запас оставлен на седьмую-восьмую строку «Работ» и длинные названия.

**Не сошлось — не переделывайте вслепую:** раздел 1.6 разбирает 3 ошибки
этого шага, каждую с признаком, по которому её видно в своём результате.

## 1.6. Типичные ошибки

Все три измерены прогоном проверки на этом же материале
(`data\reference_answers.md`, раздел «Обе половины примера»).

```
Ошибка: перечислить инструменты списком, а работы описать без них
Почему выглядит правильно: список инструментов — первое, что ищет
  рекрутер, и он в резюме есть
Почему неправильно: прогон на незаполненном шаблоне даёт 8 [FAIL] подряд
  вида «инструмент «SQL» назван, но ни одна строка «Работ» его не
  подтверждает» — ровно восемь названных инструментов и ноль
  подтверждений
Как правильно: назвать инструмент внутри строки работы; список
  «Инструменты» собрать из них
```

```
Ошибка: описать работу без числа — «построил дашборд по тендерам»
Почему выглядит правильно: факт назван, и он верный
Почему неправильно: на шаблоне это даёт 6 [FAIL] «строка «Работ» без
  единого числа»; строка с числом отличается от неё тем, что её можно
  проверить открытием файла — «74 тендера категории за период»
Как правильно: число и путь в той же строке
```

```
Ошибка: сослаться на файл, которого нет — переименовали или не создали
Почему выглядит правильно: путь выглядит настоящим и написан по правилам
Почему неправильно: проверка открывает путь на диске; на эталонном
  резюме до починки переноса строк не находился ни один из 6 путей, при
  том что все шесть файлов существовали
Как правильно: прогнать проверку до отправки резюме, а не после
```

## 1.7. Честная оценка времени

собрать и сократить текст до одной страницы — 1–1.5 ч, довести проверку
до нуля `[FAIL]` — 0.5 ч.

Оценка проектная, не измерена: `research/self.md` пуст, блок не проходил

(решение 37), а не замером.

## 1.8. Вопрос уровня собеседования

«В резюме написано: из 361 кода найдено 245. Откуда взялись 116
ненайденных и что вы с ними сделали в отчёте?»

Эталон ответа — покрыть ≥3 из 4 пунктов:

1. Названа главная причина потери и её характер: 111 из 116 — коды
   другого реестра (десятизначные РНОКПП физлиц), то есть потеря
   структурная, а не дефект сопоставления.
2. Названо, что остаток разобран до конца: необъяснённых 0.
3. Названо, что решение по остатку меняет ответ: 100 889 609.46 против
   86 108 542.77 грн, разница 14.7%.
4. Сказано, что выбор правила — за заказчиком отчёта, а в отчёт идут оба
   числа с названным правилом отбора.
