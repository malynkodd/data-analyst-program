## 1.2. Теория своими словами

**Тип — это то, что можно сделать со значением.** `"49088,78"` — строка:
её можно склеить и разрезать, но не сложить. `49088.78` — число: его можно
сложить, но нельзя искать в нём подстроку. А `csv.DictReader` отдаёт
**всё** строками — суммы и даты в том числе. Поэтому первое действие
любого расчёта — превратить строку в число. И запятую на точку при этом
придётся заменить руками: `float("49088,78")` возбуждает `ValueError`.

**Четыре контейнера и одна причина выбрать каждый.**

| Контейнер | Запись | Когда берут | Что теряет |
|---|---|---|---|
| список `list` | `[1, 2, 3]` | порядок важен, элементы повторяются | ничего; поиск по значению медленный |
| кортеж `tuple` | `(code, total)` | пара/тройка, которую не меняют | изменяемость |
| множество `set` | `{"a", "b"}` | нужны только уникальные, порядок не важен | порядок и повторы |
| словарь `dict` | `{"a": 1}` | нужен поиск по ключу за одно действие | все значения, кроме последнего, если ключ повторился |

Последняя клетка таблицы — источник самой дорогой ошибки этого шага.
Запись `names[code] = row["partner_name"]` в цикле оставляет **последнее**
написание названия партнёра и молча выбрасывает остальные. В этом датасете
у кода `30000036` пять разных написаний, и какое из них попадёт в
справочник, решает порядок строк в файле — больше ничего.

**Индекс и срез.** `pages[0]` — первый элемент, `pages[-1]` — последний,
`ordered[:5]` — первые пять, `d[6:]` — часть строки `01.01.2026` от
седьмого символа, то есть `2026`. Срез не меняет исходный объект, а
возвращает новый.

**Цикл `for` идёт по элементам, а не по номерам.** `for row in rows:` даёт
сам словарь строки; `for code, total in totals.items():` — сразу ключ и
значение, потому что каждый элемент `.items()` — кортеж из двух, и он
распаковывается в две переменные. `while` нужен там, где число повторов
заранее неизвестно — в этом шаге он встречается один раз, на страницах
`fees_api.json`.

**`if / elif / else` проверяет условия сверху вниз и останавливается на
первом истинном.** Порядок веток — часть логики, а не оформление:
`if x < 60000` перед `if x < 20000` съедает вторую ветку целиком.

**Функция возвращает значение через `return`.** Функция без `return`
возвращает `None`, и `total = my_sum(rows)` кладёт `None` в `total`, не
падая. Признак в своём результате — `TypeError` двумя строками ниже, а не
в самой функции.

**Comprehension — это цикл, записанный одним выражением.**
`[row["payout_id"] for row in rows if row["status"] == "PAID"]` читается
как «взять `payout_id` из каждой строки, где статус `PAID`». По смыслу он
не быстрее цикла — он короче. Отсюда и правило: уместен там, где тело
цикла влезает в одно выражение, и неуместен там, где не влезает.

**`try` / `except` ловит именно ту ошибку, которую вы ждёте.**
`except ValueError:` — да. Голый `except:` или `except Exception: pass` —
нет: он проглотит заодно и опечатку в имени ключа, а вы об этом никогда
не узнаете. Подробный разбор антипаттерна — `step-04.md`, 1.2.

Справочник по типам и операциям —
[Built-in Types](https://docs.python.org/3/library/stdtypes.html),
по спискам, словарям и множествам —
[Data Structures](https://docs.python.org/3/tutorial/datastructures.html).

## 1.3. Разобранный пример на сквозном датасете

Прогон на машине автора 2026-08-24, `.venv` из `step-01.md`, Python 3.11.9.
`pandas` в этом шаге не импортируется ни разу.

Чтение — четыре строки на стандартной библиотеке. Файл тот же, что в
`step-03.md`, кодировка та же (`cp1251`), разделитель тот же (`;`):

```python
import csv
from pathlib import Path

RAW = Path("program/M5/data/raw")

def read_q1() -> list[dict]:
    with (RAW / "payouts_2026_q1.csv").open(encoding="cp1251", newline="") as fh:
        return list(csv.DictReader(fh, delimiter=";"))

rows = read_q1()
print(len(rows), type(rows[0]))
```

```
1996 <class 'dict'>
```

`rows` — список из 1996 словарей. Один словарь — одна выплата, ключи
словаря — имена колонок:

```python
print(rows[0])
```

```
{'payout_id': '1000001', 'partner_code': '30000148',
 'partner_name': 'ТОВ «КОБЗА ЛОГІСТИК»', 'payout_date': '01.01.2026',
 'amount': '49088,78', 'currency': 'UAH', 'status': 'PENDING'}
```

Все семь значений — строки. `amount` — тоже строка, и с запятой.

**Задача примера: сколько выплат в каждом статусе.** Словарь-счётчик,
цикл, `dict.get` со значением по умолчанию:

```python
counts = {}
for row in rows:
    status = row["status"]
    counts[status] = counts.get(status, 0) + 1
print(counts)
```

```
{'PENDING': 189, 'PAID': 1699, 'FAILED': 108}
```

189 + 1699 + 108 = 1996 — сходится с числом строк, и это единственная
проверка, которая здесь возможна без второго источника.

**То же тремя другими способами — и что каждый теряет.**

```python
statuses = [row["status"] for row in rows]      # comprehension: список из 1996 строк
unique = set(statuses)                          # множество: 3 элемента, порядок потерян
paid = [row for row in rows if row["status"] == "PAID"]   # фильтр: 1699 словарей
print(len(statuses), sorted(unique), len(paid))
```

```

```

**Ловушка словаря, измеренная на этих данных.** Справочник «код →
название» одной строкой в цикле:

```python
names = {}
for row in rows:
    code = row["partner_code"].strip()
    if code:
        names[code] = row["partner_name"]        # последнее вхождение побеждает
print(len(names), repr(names["30000036"]))
```

```python
        if code not in names:
```

Кодов в обоих случаях 57, а название у одного и того же кода — разное:

```python
variants = {}

print(sum(len(v) for v in variants.values()))
```

## 1.4. Задание

Все пятнадцать функций пишутся в один файл `program\M5\work\basics.py`.
Файл ничего не читает с диска и ничего не печатает: строки и страницы
приходят аргументом. `import pandas` в этом файле запрещён — он есть в
критерии 1.5.

Первые две задачи — **ведомые**: каркас дан, дописываются помеченные
строки. Остальные тринадцать — самостоятельные.

1. **[ведомая]** `to_amount(text) -> float` — превращает `"49088,78"` в
   `49088.78`. Каркас:

   ```python
   def to_amount(text: str) -> float:
       return float(text.replace(..., ...))   # чем заменить что
   ```

2. **[ведомая]** `total_amount(rows) -> float` — сумма `amount` по всем
   строкам, округлённая до второго знака. Каркас:

   ```python
   def total_amount(rows: list[dict]) -> float:
       total = 0.0
       for row in rows:
           total += ...                        # одна строка
       return round(total, 2)
   ```

3. `paid_amount(rows) -> float` — то же, но только по строкам со статусом
   `PAID`.
4. `count_by_status(rows) -> dict[str, int]` — словарь «статус → сколько
   строк».
5. `unique_codes(rows) -> set[str]` — множество непустых `partner_code`.
   Именно множество, а не список: тип проверяется.
6. `rows_without_code(rows) -> int` — сколько строк с пустым
   `partner_code`.
7. `size_bucket(value) -> str` — по сумме возвращает `"малая"` при
   `value < 20000`, `"средняя"` при `20000 <= value < 60000` и
   `"крупная"` при `value >= 60000`.
8. `bucket_counts(rows) -> dict[str, int]` — сколько строк в каждой из
   трёх групп. Все три ключа обязаны быть в словаре, даже если группа
   пуста.
9. `big_paid_ids(rows, limit) -> list[str]` — отсортированный список
   `payout_id` тех выплат, где статус `PAID` и сумма строго больше
   `limit`. Напишите его comprehension'ом.
10. `top_partners(rows, n) -> list[tuple[str, float]]` — `n` пар
    «код партнёра, сумма `PAID`», по убыванию суммы; при равных суммах —
    по коду по возрастанию. Суммы округлены до второго знака, строки с
    пустым кодом не участвуют.
11. `period(rows) -> tuple[str, str]` — пара «самая ранняя дата, самая
    поздняя дата» в том же виде `дд.мм.рррр`. Сравнивать строки напрямую
    нельзя: `31.01.2026` больше `01.03.2026` как текст.
12. `page_item_counts(pages) -> list[int]` — сколько элементов на каждой
    странице `fees_api.json`, в порядке страниц. Напишите **`while`**, а
    не `for`: это единственное место шага, где он нужен.
13. `unique_fee_ids(pages) -> set[int]` — множество всех `payout_id` из
    всех страниц.
14. `name_variants(rows) -> dict[str, int]` — словарь «код партнёра →
    сколько разных написаний названия у него в файле». Сравнение строгое.
15. `partner_names(rows) -> dict[str, str]` — справочник «код → название»,

## 1.6. Типичные ошибки

Все четыре измерены на этом датасете при написании шага и его эталона.

**Ошибка:** складываете `amount` как есть, без замены запятой на точку.
**Почему выглядит правильно:** в файле стоит `49088,78` — на человеческий
взгляд число, и `csv` прочитал его без единой жалобы.
**Почему неправильно:** `float("49088,78")` возбуждает
`ValueError: could not convert string to float`, и скрипт падает на
первой же строке. Это ещё повезло. Второй вариант хуже: сложите строки
через `+`, и 1996 значений склеятся в одну строку длиной 17 000 символов.
`total` окажется не числом, а текстом, и падать ничего не станет.
**Как правильно:** `float(text.replace(",", "."))` — одной функцией
`to_amount`, чтобы замена жила в одном месте, а не в пятнадцати.

**Ошибка:** строите справочник «код → название» присваиванием в цикле
без проверки `if code not in names`.
**Почему выглядит правильно:** длина словаря — 57, ровно столько же,
сколько при любом другом способе. Ни ошибки, ни предупреждения.
**Почему неправильно:** у кода `30000036` в файле **5** написаний, и
словарь оставляет одно — `'ПП «КАШТАН МАРКЕТ»'` вместо
`'ПП  «Каштан  Маркет»'`, если побеждает последнее. Всего теряется
251 − 57 = **194** написания, и именно на них в `step-05.md` разойдётся
соединение по названию.
**Как правильно:** решить явно, какое вхождение побеждает, и записать это
условием; если нужны все — значением словаря делается множество, а не
строка.

**Ошибка:** сравниваете даты `дд.мм.рррр` как строки, чтобы найти границы
периода.
**Почему выглядит правильно:** `min()` и `max()` на списке строк
отрабатывают без ошибки и возвращают правдоподобные даты — обе из файла,
обе существуют.
**Почему неправильно:** на этом датасете `min()` по строкам даёт
`01.01.2026` (верно, случайно) и `max()` — `31.03.2026` (тоже верно,
тоже случайно), потому что дни от 01 до 31 сортируются как текст в том же
порядке, что и числа. Пусть период начнётся не первого числа — и первой датой
станет `01.02.2026` вместо `15.01.2026`. Проверка, которая проходит на
одних данных и молча ломается на других, — не проверка вовсе.
**Как правильно:** сортировать по ключу, который переставляет части даты
в порядок «год, месяц, день»: `key=lambda d: (d[6:], d[3:5], d[:2])`.

**Ошибка:** ставите в `size_bucket` условия в порядке «сначала крупная».
**Почему выглядит правильно:** три ветки на месте, функция возвращает
строку на любом входе — а тестов на границы никто и не писал.
**Почему неправильно:** `if value < 60000: return "средняя"` первой
веткой съедает и малые суммы: все 561 строки группы «малая» уедут в
«среднюю». Итог при этом сойдётся — 1996, — и по нему ошибку не увидеть.
Ловится она только границами: 19 999.99 обязана дать «малая», 20 000.00 —
«средняя», 60 000.00 — «крупная».
**Как правильно:** ветки идут от самого узкого условия к самому широкому;
`elif`, а не три независимых `if`.

`{"partner": str, "amount": float, "status": str}`. Напишите функцию,
которая возвращает словарь «партнёр → сумма по строкам со статусом
`PAID`». Без pandas. Что вы уточните до того, как начнёте писать?»

**Эталон (ответ покрывает ≥3 из 4 пунктов):**
1. Пишет цикл со словарём-накопителем и `dict.get(key, 0)` либо
   `defaultdict(float)`; возвращает словарь, а не печатает его.
2. Уточняет, что делать со строками, где `partner` пуст или отсутствует
   ключ: включать отдельной группой, выбрасывать или падать — и называет
   выбранное поведение вслух.
3. Называет, что делать с регистром и пробелами в имени партнёра: без
   нормализации `«Каштан Маркет»` и `«КАШТАН МАРКЕТ»` — два разных ключа.
4. Отмечает, что `amount` может прийти строкой, и тогда сложение даст
   склейку текста, а не сумму, — то есть тип входа надо либо
   гарантировать, либо проверять.
