## 1.2. Теория своими словами

**Excel-файл — это не таблица, а книга листов, и шапка в нём где угодно.**
У [`pandas.read_excel`](https://pandas.pydata.org/docs/reference/api/pandas.read_excel.html)
за это отвечают два параметра: `sheet_name` — какой лист читать, и
`header` — «Row (0-indexed) to use for the column labels of the parsed
DataFrame». В `partners.xlsx` первая строка занята заголовком выгрузки, а
имена колонок стоят во второй, то есть `header=1`.

**Вложенный JSON не читается как таблица одной командой.** `pd.read_json`
на этом файле падает — текст исключения в 1.6. Рабочий путь: прочитать
файл `json.loads`, а затем развернуть нужный уровень
[`pandas.json_normalize`](https://pandas.pydata.org/docs/reference/api/pandas.json_normalize.html)
(«Normalize semi-structured JSON data into a flat table»), указав
`record_path` — путь к списку записей внутри каждой страницы.

**Склейка требует одинаковых имён колонок.**
[`pandas.concat`](https://pandas.pydata.org/docs/reference/api/pandas.concat.html)
складывает объекты по оси, а колонки, которые есть не у всех, заполняет
`NaN`: «Columns outside the intersection will be filled with `NaN`
values». Ошибки при этом нет — есть таблица с лишними колонками, где
половина значений пуста. Поэтому вторая выгрузка приводится к схеме первой
**до** склейки: `paid_at` → `payout_date`, `total` → `amount`.

**Дедупликация — это не одна операция, а три ответа.** По какому полю
снимаются дубли, какая запись остаётся и что делать со строками, где поле
пусто. Третий ответ обходится дороже двух первых: `drop_duplicates` по
колонке кода схлопывает и пустые коды тоже, и вместо пяти записей без
кода в справочнике остаётся одна. Число строк после этого — 56, а не 60, и
дальше расходится всё (`data/reference_answers.md`, раздел «Наивный
merge»: разница 1876 строк).

**Четыре файла читаются четырьмя функциями, и падение одной уносит
результат остальных трёх.**

Умение B1 — «дана папка из 4 файлов с разными кодировками,
разделителями и заголовками». Пока все четыре на месте и целы, скрипт
из четырёх вызовов подряд работает прекрасно. Но стоит одному файлу
оказаться испорченным, переименованным или недокачанным — исключение
поднимается из середины скрипта, и всё прочитанное до него уходит вместе
с процессом.

На работе это штатная ситуация, а не авария: выгрузку кладут в папку по
расписанию, и один из файлов приходит битым чаще, чем хотелось бы.
Отчёт «прочитано 3 из 4, четвёртый — вот такая ошибка» полезнее, чем
отсутствие отчёта.

Конструкция для этого одна:

```python
def safe_load(name, fn):
    try:
        df = fn()
        return name, df, None
    except Exception as exc:
        return name, None, f"{type(exc).__name__}: {exc}"
```

`try` — блок, который может упасть; `except Exception as exc` — что
делать, если упал; `exc` — сам объект ошибки, из которого берутся её
класс и текст. Возвращать здесь надо **и то, и другое**: таблицу, если
получилось, и текст ошибки, если нет.

Чего в этом блоке делать нельзя — глотать ошибку молча:

```python
try:
    df = fn()
except Exception:
    df = pd.DataFrame()      # ← так не пишут
```

Пустая таблица вместо ошибки означает вот что: дальше по коду выгрузка
считается прочитанной и пустой, а не непрочитанной. Разница огромная.
`concat` склеит её без единого предупреждения, и в итоговой таблице
просто не окажется четверти строк — тот же исход, что и при молчаливой
потере на join'е из шага 04.

Документация:
[Errors and Exceptions](https://docs.python.org/3/tutorial/errors.html)
— раздел «Handling Exceptions».

## 1.6. Типичные ошибки

**Ошибка:** ловите исключение и подставляете вместо непрочитанного файла
пустой `DataFrame`.
**Почему выглядит правильно:** скрипт перестал падать, отчёт строится,
код возврата 0 — все признаки успеха налицо.
**Почему неправильно:** пустая таблица означает «файл прочитан, в нём
ноль строк», а не «файл не прочитан». `concat` склеит её молча, и в
итоговой таблице не будет строк четвёртого источника — при чтении
`fees_api.json` это **3372** записи комиссий на двенадцати страницах
(база — все страницы файла, ключ страницы `items`, дубли на границах
страниц не сняты — их 11, `data/reference_answers.md`). Отчёт по take
rate в шаге 05 посчитается тогда на пустой комиссии и даст ноль вместо
расхождения.
Ошибки при этом не будет ни одной.
**Как правильно:** возвращать `None` и текст ошибки, а не пустую
таблицу; в отчёт писать «прочитано N из 4» и класс исключения.
Отсутствие данных обязано выглядеть как отсутствие данных.

**Ошибка:** пишете `except:` без указания класса или `except Exception:
pass`.
**Почему выглядит правильно:** короче, и «ловит всё» звучит надёжнее, чем
список конкретных классов.
**Почему неправильно:** голый `except:` перехватывает и `KeyboardInterrupt`
с `SystemExit` — скрипт перестаёт останавливаться по Ctrl+C. А `pass`
стирает текст ошибки, и вместо `FileNotFoundError` с именем файла в
отчёте остаётся тишина: непрочитанный файл ничем не отличается от
прочитанного пустого.
**Как правильно:** `except Exception as exc` и обязательное сохранение
`type(exc).__name__` и текста в отчёт.


Все пять измерены на этом датасете.

**Ошибка:** читаете JSON через `pd.read_json` — «для JSON есть своя
функция».
**Почему выглядит правильно:** функция существует, файл — валидный JSON,
и для плоского JSON это ровно тот путь, что нужен.
**Почему неправильно:** падает с `ValueError: Mixing dicts with non-Series
may lead to ambiguous ordering.` — файл состоит из 12 страниц, внутри
каждой список элементов, внутри элемента ещё один объект `fee`.
**Как правильно:** `json.loads` и `pd.json_normalize(payload["pages"],
record_path="items")` — 3372 элемента, три колонки, включая развёрнутые
`fee.amount` и `fee.currency`.

**Ошибка:** читаете лист «Партнери» без `header`.
**Почему выглядит правильно:** таблица читается, ошибки нет, данные на
месте. Придраться не к чему, пока не посмотришь на имена колонок.
**Почему неправильно:** именами колонок становятся `Довідник партнерів.
Вигрузка з CRM` и четыре `Unnamed: 1`…`Unnamed: 4`, а строк получается
**64** вместо 63 — настоящая строка заголовков попадает в данные. Обратиться
к колонке `Код ЄДРПОУ` после этого нельзя: такой колонки в таблице нет.
**Как правильно:** `header=1`. Проверка — печать `list(df.columns)` сразу
после чтения, до любых расчётов.

**Ошибка:** снимаете дубли справочника одним `drop_duplicates(subset=["Код
ЄДРПОУ"])`.
**Почему выглядит правильно:** дубли по коду и правда снимаются, три
лишние строки уходят, отчёт собирается без ошибок.
**Почему неправильно:** остаётся **56** строк вместо 60: пять записей без

**Как правильно:** снимать дубли только среди строк с непустым кодом.
Число в `load_report.csv` — 60, и определение к нему записано в 1.3.

**Ошибка:** склеиваете выгрузки, не приведя схему.
**Почему выглядит правильно:** `concat` не падает, строк ровно 4144 —

**Почему неправильно:** колонок становится **9** вместо 7, а

**Ошибка:** отбираете выплаты сравнением `status == "PAID"`.

**Почему неправильно:** получается **1699** строк вместо **3534**: вся

## 1.8. Вопрос уровня собеседования

**Вопрос:** «Вы собрали месячный отчёт из двух выгрузок одной системы.
Строк ровно столько, сколько ожидали, ошибок нет, но сумма примерно вдвое
меньше, чем в бухгалтерии. С чего начнёте?»

**Эталон (ответ покрывает ≥3 из 4 пунктов):**
1. Проверяет схему обеих выгрузок до склейки — совпадают ли имена колонок;
   называет, что при несовпадении склейка добавляет колонки и заполняет их
   пропусками, не сообщая об этом.
2. Считает пропуски в колонке суммы после склейки и смотрит, приходятся ли
   они целиком на одну из выгрузок.
3. Считает контрольные числа по каждому источнику отдельно и складывает —
   сравнение источник-к-источнику, а не только итога с итогом.
4. Отмечает, что совпадение числа строк ничего не доказывает: строки на
   месте, а значения в них пусты.
