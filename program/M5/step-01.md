## 1.1. Цель и связь с умением

После шага на машине есть отдельное окружение с четырьмя пакетами, папка
`program\M5\data\raw\` заполнена, а её содержимое доказано совпадающим с
тем, на котором посчитаны все эталоны модуля: четыре числа строк и четыре
sha256.

Шаг инфраструктурный, умения не несёт. Строгость критерия от этого не
меняется. Причина, по которой сверка обязательна до первой задачи: все
критерии шагов 02–09 — это числа с данных. Если данные разошлись, шаг 05
не сойдётся с эталоном, и по одному расхождению нельзя будет сказать, что
сломано — ваш join или сам датасет.

## 1.2. Теория своими словами

**Виртуальное окружение — это отдельный набор пакетов для одной работы.**
Документация [venv](https://docs.python.org/3/library/venv.html): «A
virtual environment is created on top of an existing Python installation
<…> and by default is isolated from the packages in the base environment,
so that only those explicitly installed in the virtual environment are
available». Практический смысл здесь ровно один: версия pandas, на которой
считаны эталоны, перестаёт зависеть от того, что стоит в системе и что
поставится туда через полгода.

Активировать окружение не нужно. Вместо `Activate.ps1` в шагах модуля
интерпретатор вызывается путём: `.venv\Scripts\python.exe`. Причина не в
экономии символов: так не остаётся состояния, которое можно забыть
включить, и `sys.executable` в любой момент честно отвечает, какой именно
Python отработал.

**Версии зафиксированы, потому что на них считаны эталоны.** `pandas` и
`openpyxl` ставятся точными версиями — это единственные два пакета,
которые влияют на числа. `matplotlib` и `pytest` на числа не влияют
(рисунок и запуск тестов), их версии записываются, но совпадения с
авторскими не требуют. Развилок по другим версиям и другим ОС в тексте
модуля нет (решение 21, п. 4); отложенное — в `DEFERRED.md`.

**Данных в репозитории нет, есть генератор.** Папка `program\M5\data\raw\`
перечислена в корневом `.gitignore` (решение 29 `design/decisions.md`): в
git лежат `generate_m5.py`, `reference_m5.py`, четыре эталонных CSV и
`reference_answers.md`. Датасет появляется прогоном и обязан появиться
побайтово таким же — генератор детерминирован, `SEED = 20260817`.

**Контрольная точка — это sha256, а не число строк.** Число строк
совпадает и у разных датасетов — проверено в 1.3. Из двух величин только
хэш отличает «те же данные» от «похожих данных».

## 1.3. Разобранный пример на сквозном датасете

Прогон на машине автора 2026-08-19, тот же Python 3.11.9, что поставлен в
M0.

Окружение собралось за 53 с и заняло 243 МБ; в нём 22 пакета, из них
четыре названы прямо, остальные пришли зависимостями (`numpy` 2.4.6,
`pillow`, `fonttools` и другие). Версии:

```
pandas 3.0.5
openpyxl 3.1.5
matplotlib 3.11.1
pytest 9.1.1
```

Четыре sha256 из прогона `generate_m5.py` совпали с таблицей
`data/reference_answers.md` — всеми 64 знаками каждый:

```
payouts_2026_q1.csv   4a7619c61b5d6566c405b22232c95c078d22c1e0c3b372937cc710af282055c8
payouts_2026_q2.csv   c17f80ac474d5f30d276626caf987edc7245f38cc60a259ab278744fe5f50c15
partners.xlsx         7bb4bf4ba81e5dec813bbe3e976b2a675efa896407e354228f0bb8d7b754632d
fees_api.json         d2e79b0b7b9e97e5cf6a46e125d4bf4076884596d69fb6aa665a04c58896bde0
```

**Почему сверяется хэш, а не число строк.** Тот же генератор запущен с
`SEED = 99` — одна изменённая строка, всё остальное то же. Результат:
`partners.xlsx` дал **те же 63 строки**, `fees_api.json` — **3373** против
3372, то есть отличие на единицу, которое легко списать на невнимательное
чтение. При этом **все четыре sha256 оказались другими**:

```
payouts_2026_q1.csv   2077  1b3eb5d02446717c627c1028769d130f9c203286290decf02d2d8b17676acf0a
partners.xlsx           63  47779d809807a76cda17f9a5a08464cb9a0b339e5d3e726069a71f07cb55556f
```

Один из четырёх файлов по числу строк неотличим от эталонного, а данные в
нём другие целиком. Отсюда порог критерия ниже — по хэшам, а число строк
идёт довеском.

## 1.4. Задание

1. Создайте окружение в корне репозитория и обновите в нём `pip`:

   ```
   > python -m venv .venv
   > .venv\Scripts\python.exe -m pip install --upgrade pip
   ```

2. Поставьте четыре пакета; первые два — точными версиями:

   ```
   > .venv\Scripts\python.exe -m pip install pandas==3.0.5 openpyxl==3.1.5 matplotlib pytest
   ```

3. Убедитесь, что дальше работает именно это окружение, а не системный
   Python:

   ```
   > .venv\Scripts\python.exe -c "import sys; print(sys.executable)"
   ```

4. Запишите четыре версии в `research/self.md` — датой и строкой на
   пакет. Понадобятся, когда очередное обновление изменит поведение.

5. Соберите датасет:

   ```
   > .venv\Scripts\python.exe program\M5\data\generate_m5.py
   ```

6. Сверьте вывод генератора с двумя местами `data/reference_answers.md`:
   таблицей контрольной точки (четыре файла: строки и sha256) и абзацем
   инвариантов под ней (4144 выплаты, 60 партнёров, из них 5 без кода, 63
   строки с дублями, 2 кода вне справочника, 127 дней с курсом, 12 страниц
   комиссий, 11 дублей на границах, 170 выплат без рассчитанной комиссии,
   3 — без курса вовсе).

7. Заведите папку для своего кода и первый коммит модуля:

   ```
   > mkdir program\M5\work
   > git add program\M5\work
   > git commit -m "M5: окружение и датасет"
   ```

   Пустую папку git не хранит — положите в неё `.gitkeep` (пустой файл)
   или сразу файл с записанными версиями. Проверьте, что `git status` не
   показывает ни `.venv/`, ни `program/M5/data/raw/`: обе строки уже есть
   в корневом `.gitignore`, и попадание любой из них в индекс означает,
   что правило не сработало.

## 1.5. Критерий готовности

Шесть проверок, каждая — «да/нет» без второго человека.

| Проверка | Эталон | Допуск |
|---|---|---|
| `.venv\Scripts\python.exe -V` | `Python 3.11.9` | точное совпадение строки |
| `sys.executable` | путь оканчивается на `\.venv\Scripts\python.exe` | точное совпадение хвоста пути |
| версии `pandas` и `openpyxl` | `3.0.5` и `3.1.5` | точное совпадение: на этих версиях считаны эталоны модуля |
| версии `matplotlib` и `pytest` | у автора `3.11.1` и `9.1.1` | совпадение не требуется, требуется запись в `research/self.md` |
| четыре sha256 в выводе генератора | таблица контрольной точки `data/reference_answers.md` | расхождение 0 знаков из 64 в каждом из четырёх |
| четыре числа строк и десять инвариантов в выводе генератора | та же таблица и абзац под ней | расхождение 0 |

файла. Числа строк при этом могут сойтись — см. 1.3.

Норматив по времени: ≤2 ч на всё, кроме чтения `reference_answers.md`.
Больше — строка в `research/self.md` с причиной.

**Не сошлось — не переделывайте вслепую:** раздел 1.6 разбирает 3 ошибки
этого шага, каждую с признаком, по которому её видно в своём результате.

## 1.6. Типичные ошибки

**Ошибка:** ставите пакеты в системный Python, без окружения.
**Почему выглядит правильно:** команда проходит, `import pandas`
работает, ничего никуда не падает. На машине автора `python -m pip install
pandas` печатает `Requirement already satisfied` — pandas там уже стоит.
**Почему неправильно:** в системном Python этой машины **30** пакетов
против 22 в окружении модуля, и версия pandas в нём меняется от любой
чужой установки. Эталоны модуля посчитаны на 3.0.5; расхождение в версии
не даёт сообщения об ошибке — оно даёт другое число в критерии шага 04.
**Как правильно:** `python -m venv .venv`, дальше везде
`.venv\Scripts\python.exe`. Проверка — `sys.executable`: у окружения путь
оканчивается на `\.venv\Scripts\python.exe`, у системного — на
`\Programs\Python\Python311\python.exe`.

**Ошибка:** сверяете контрольную точку по числу строк, хэши пропускаете —
их неудобно сравнивать глазами.
**Почему выглядит правильно:** четыре числа сошлись, файлы на месте,
генератор отработал без единой ошибки. Что ещё проверять.
**Почему неправильно:** измерено в 1.3 — на `SEED = 99` `partners.xlsx`
даёт те же **63** строки, `fees_api.json` — **3373** вместо 3372, а
содержимое всех четырёх файлов другое. Число строк отвечает на вопрос
«столько же». Вопрос был другой: «то же самое».
**Как правильно:** сверять все четыре sha256 целиком. Сравнение хвоста в
8 знаков не годится: у двух прогонов из примера совпадающих хвостов нет,
но и гарантии, что их не будет, тоже нет — сравнивается вся строка.

**Ошибка:** запускаете генератор до установки пакетов — датасет
синтетический, «зависимостей у него быть не должно».
**Почему выглядит правильно:** три файла из четырёх генератор пишет
стандартной библиотекой, а `openpyxl` нужен ему только под xlsx —
казалось бы, три четверти работы пройдут в любом случае.
**Почему неправильно:** импорт стоит в начале файла, поэтому падение
приходит раньше, чем будет записан хоть один файл. В голом окружении
измерено:
`ModuleNotFoundError: No module named 'openpyxl'` на строке 58
(`from openpyxl import Workbook`). Папка `raw\` остаётся пустой целиком, а
не на три файла из четырёх.
**Как правильно:** сначала `pip install`, потом генератор. `openpyxl`
нужен и генератору, и шагу 04, где читается `partners.xlsx`.

## 1.8. Вопрос уровня собеседования

**Вопрос:** «Расчёт, который вы сдали месяц назад, коллега воспроизвёл у
себя и получил другое число. Код тот же, данные те же. Что вы проверите
первым?»

**Эталон (ответ покрывает ≥3 из 4 пунктов):**
1. Проверяет, что данные действительно те же, — контрольной суммой файла,
   а не числом строк и не датой выгрузки.
2. Называет версии: интерпретатор и версии библиотек расчёта; говорит,
   как их зафиксировать (окружение с точными версиями, файл со списком).
3. Называет окружение как отдельную причину: расчёт мог идти в системном
   Python с чужим набором пакетов.
4. Отмечает, что расхождение без сообщения об ошибке опаснее падения:
   искать его придётся сверкой промежуточных чисел, поэтому в расчёте
   нужны печатаемые промежуточные итоги.
