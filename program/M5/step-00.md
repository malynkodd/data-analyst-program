# M5.00. Декларация модуля (умения, разбивка, датасет, предусловие)

Не шаг для учащегося — служебный файл, требуемый разделом 1.3 скилла
curriculum-design: датасет, схема и разбивка умений объявляются на весь
модуль один раз, до первого содержательного шага. Команд не содержит и
данных не грузит (решение 20 `design/decisions.md`).

**Первый модуль, который пишется по решению 28** (2026-08-17): восемь
блоков шага применяются в сокращённом виде — теория вдвое, только
измеренные ошибки, шаги укрупнены до потолка 10 ч. Сокращается упаковка;
покрытие умений, критерии с эталоном и практика на данных — нет. Проверить
это на M5 и есть смысл захода: модуль самый большой в программе.

## Умения модуля и разбивка по шагам

Модуль M5 закрывает **B1–B5** — часть 2.1 blueprint. Все пять умений
остаются, ни одно не сокращено и не перенесено. Семь шагов, из них один
инфраструктурный (порог решения 23 — «не больше двух на модуль и не больше
четверти шагов» — не превышен: 1 из 7).

| Шаг | Умение | Что делает учащийся | Время |
|---|---|---|---|
| `step-01.md` | — (инфраструктура) | Окружение: Python автора, `venv`, четыре пакета, запуск генератора, сверка контрольной точки датасета | 3–4 ч |
| `step-02.md` | B1, часть 1 из 2 | Язык-минимум аналитика и **одна** выгрузка в DataFrame: cp1251, разделитель `;`, десятичная запятая, даты `дд.мм.рррр`, типы | 8–10 ч |
| `step-03.md` | B1, часть 2 из 2 | Остальные три файла и склейка: xlsx с двухстрочной шапкой и вторым листом, вложенный JSON со страницами, вторая выгрузка с переименованными колонками | 8–10 ч |
| `step-04.md` | B2 | Три join'а по неидеальному ключу и отчёт о потерях: вход = сопоставлено + потеряно, причина каждой потери | 8–10 ч |
| `step-05.md` | B3 | Функция расчёта take rate и пять тестов `pytest`, среди них пустой вход и деление на ноль | 6–8 ч |
| `step-06.md` | B4 | Сборка в `run.py`: из чистого клона одной командой до итогового файла, ручных шагов 0 | 5–7 ч |
| `step-07.md` | B5 | График в matplotlib под конкретный вывод: два ряда по месяцам, подписи осей, единицы, легенда | 5–7 ч |

Написаны шаги 01–06: окружение и контрольная точка, первая выгрузка с
паспортом, остальные три файла и склейка, три join'а и отчёт о потерях,
функция take rate с пятью тестами pytest, `run.py` от чистого клона до
отчёта одной командой. Шаг 07 не написан.

**Почему B1 разбито на две части, а остальные умения — нет.** B1 — единственное
умение модуля, которое требует двух разных работ: сначала научиться писать
на Python и прочитать один файл правильно, потом собрать четыре файла трёх
форматов в одну таблицу. Учащийся приходит в M5 с нулём написанного
Python: в M0 он запускал готовые скрипты (умение I2), а не писал свои.
Складывать это в один шаг — значит поставить шаг на 16–20 ч, что запрещено
потолком решения 28 (10 ч). Остальные четыре умения формулируются как одна
работа каждое и делятся только по частям задания, а не по шагам.

## Часовой бюджет — сумма вне вилки, и она не правится этим заходом

Построчная сумма семи шагов: 3–4 + 8–10 + 8–10 + 8–10 + 6–8 + 5–7 + 5–7 =
**43–56 ч** при вилке части 6.1 blueprint **80–120 ч**. Сумма целиком ниже
вилки — разрыв 37–64 ч, самый большой в программе.

Вилка **не правится**, и это решение 24: сумма шагов — факт, вилка —
оценка, но правится вилка только тогда, когда искать недостающее
содержание больше негде. Здесь искать есть где: ни одного шага не
написано, и оценки выше — проектные. Ровно так закрывался тот же разрыв в
M3 (37–47 при 60–80; заход 5 зафиксировал, заход 6 закрыл содержанием,
часы 6.1 не менялись). Порядок для M5 тот же: сначала семь шагов, потом
разговор о вилке.

Три причины, по которым сумма может оказаться заниженной именно здесь, —
названы заранее, чтобы при правке не выдумывать их задним числом:

1. **Python с нуля.** Это единственный модуль, где у учащегося нет
   никакого предыдущего опыта в инструменте: в M2 были таблицы, в M3 SQL
   поверх таблиц, в M4 BI поверх SQL. Оценка 8–10 ч на «язык-минимум плюс
   первый файл» проверена ничем.
2. **Вилка [М] 80–120 — не оценка автора**, а строка топ-15
   `research/market.md` для «Python (pandas/numpy)» целиком, включая то,
   что B1–B5 не требуют.
3. **Отладка не оценивается по тексту.** Три из шести находок прогона
   pandas (`reference_answers.md`, последний раздел) — молчаливые: код
   работает и даёт неверное число. Время на такую отладку в проектной
   оценке не сидит, потому что автор находил их с готовым эталоном в руке.

## Датасет — синтетика с генератором, отступление объявлено

Домен fintech (решение 21, п. 2): платёжный сервис, выплаты партнёрам.
Файлы, форматы, числа и контрольная точка — `data/README.md` и
`data/reference_answers.md`; здесь не дублируются.

Категория — **синтетика с генератором**, хотя M5 ведёт к проекту P4, для
которого раздел 1.3 скилла требовал реальных данных со снапшотом. Правило
скилла переписано **решением 29** (`design/decisions.md`, 2026-08-17):
категорию определяет роль файла, а не проект, к которому модуль ведёт.
Учебный модуль работает на синтетике, потому что эталон обязан быть
известен точно, а агент данные не скачивает; реальные публичные источники
остаются в самом P4 (Prozorro + ЄДР + НБУ, часть 5 blueprint) и в M6.
То же отступление и по той же причине сделано в M4 (решение 25).

**Что в датасете сломано намеренно.** Дефект без адресата в датасет не
кладётся: каждый заведён под конкретное умение и подтверждён числом.

| Дефект | Число | Под какое умение |
|---|---|---|
| Разные кодировки (cp1251 и UTF-8 с BOM) | 2 файла | B1 |
| Разные разделители и десятичный знак | `;` и запятая против `,` и точки | B1 |
| Схема поменялась в середине ряда: две колонки переименованы, статусы в другом регистре | `payout_date`→`paid_at`, `amount`→`total` | B1 |
| Шапка xlsx в две строки; второй лист с курсом | 63 строки данных, 127 дней | B1 |
| Вложенный JSON со страницами и дублями на границах | 12 страниц, 11 дублей, 3372 против 3361 | B1, B2 |
| Дубли в справочнике по коду | 3 | B2 |
| Записи без кода: сопоставление только по названию, которое приходит с мусором (пробелы, кавычки, регистр) | 5 партнёров, 6% строк выплат | B2 |
| Код, которого нет в справочнике | 2 партнёра, 11 выплат | B2 |
| Курс только по рабочим дням и начинается позже первой выплаты | 3 выплаты без курса вовсе | B2 |
| Комиссия рассчитана не по всем выплатам | 170 | B2, B3 |

Итог по датасету: 4144 выплаты, из них `PAID` — 3534; после трёх join'ов в
отчёт доходят 3350. Все числа — `data/reference_answers.md`.

## Предусловие модуля

Версии и пути — авторские, без развилок (решение 21, п. 4). Строка про
другие ОС и другие версии — в `DEFERRED.md`.

1. **Python 3.11.9** — стоит с M0 (`program/M0/step-01.md`), заново не
   ставится.
2. **Четыре пакета в виртуальном окружении**: `pandas` 3.0.5, `openpyxl`
   3.1.5, `matplotlib`, `pytest`. Первые два измерены прогоном на машине
   автора 2026-08-17; версии matplotlib и pytest будут измерены в
   `step-01.md`, где они нужны впервые. `openpyxl` требуется и самому
   генератору — без него датасет не собирается.
3. **`generate_m5.py` прогнан, контрольная точка сошлась.** Четыре sha256
   и четыре числа строк — `data/reference_answers.md`. Расхождение
   означает другой датасет, а не другое решение задачи.
4. **Git с M0** (`init`/`add`/`commit`, решение 14): B4 проверяется
   клонированием, и без коммитов проверять нечего.

## Зависимости

`M3 → M5` — жёсткая (часть 3.2 blueprint): pandas объясняется через уже
освоенные `join`/`group by`, обратный порядок удваивает объём новых
понятий. Дальше `M5 → M6` (грязные данные требуют инструмента, который их
чинит) и `M5 + M6 + M7 → P4`.

Внутри модуля порядок шагов линейный: каждый следующий работает на
результате предыдущего, и `step-06.md` (B4) собирает воедино то, что
написано в шагах 02–05.
