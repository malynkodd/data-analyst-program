## 1.1. Цель и связь с умением

Умение B5 части 1 blueprint: «Строит график в matplotlib под конкретный

комиссии (take rate) плывёт от месяца к месяцу.

Данные для графика уже посчитаны: `data/ref_month_gross.csv` (эталон

`ref_partner_report.csv`, а собирался из `build_final()`.

## 1.2. Теория своими словами

**Два ряда с разным масштабом на одной оси прячут меньший.** Оборот в
этом датасете — десятки миллионов гривен в месяц, комиссия — сотни тысяч,
разница на два порядка. На общей оси Y линия комиссии занимает верхнюю
кромку около нуля независимо от того, как она на самом деле себя ведёт —
пример в 1.3.

**Вторая ось Y (`ax.twinx()`) не чинит это, а меняет проблему на другую.**
Программа уже запрещает двойные оси для дашбордов Power BI (P3, критерий
13 — `design/decisions.md`, раздел о вводе PBIR): у двух рядов на разных
шкалах масштаб каждой оси подбирается произвольно, и совмещение может
нарисовать корреляцию, которой нет, или спрятать реальную. Тот же принцип
здесь: `matplotlib.pyplot.subplots` с двумя рядами подграфиков и общей
осью X (`sharex=True`) показывает форму каждого ряда без риска обмана
масштабом одной оси относительно другой.

## 1.3. Разобранный пример на сквозном датасете

Прогон на машине автора 2026-08-20.

**Один общий Y — комиссия становится плоской линией у нуля:**

```python
fig, ax = plt.subplots(figsize=(7, 4))
ax.plot(g["month"], g["gross_uah"], marker="o", label="Оборот")
ax.plot(g["month"], g["fee_uah"], marker="o", label="Комиссия")
```

Измерено: диапазон оси Y — от −945 103 до 30 189 768; ряд комиссии
(470 118…576 893) занимает **0.34%** высоты графика. Обе оси подписаны,
легенда есть — критерий из 1.1, взятый формально, соблюдён, а вывод
график не поддерживает: по нему нельзя сказать ничего про комиссию, кроме
«она маленькая».

**Два подграфика с общим X — оба ряда читаемы каждый в своём масштабе:**

```python
fig, (ax1, ax2) = plt.subplots(2, 1, figsize=(7, 6), sharex=True)

ax1.plot(g["month"], g["gross_uah"] / 1e6, marker="o",
        color="#1f77b4", label="Оборот")
ax1.set_ylabel("Оборот, млн грн")
ax1.legend(loc="lower right")
ax1.set_title("Оборот и комиссия по месяцам")

ax2.plot(g["month"], g["fee_uah"] / 1e3, marker="s",
        color="#d62728", label="Комиссия")
ax2.set_xlabel("Месяц (2026)")
ax2.set_ylabel("Комиссия, тыс. грн")
ax2.legend(loc="lower right")
```

Вывод, который график поддерживает: оба ряда падают в феврале и растут к
маю одной и той же формой — take rate по месяцам (посчитан отдельно,
`fee_uah / gross_uah`) держится в узком коридоре **0.0199–0.0206**,
разброс **0.0007**. Комиссия не отстаёт от оборота и не опережает его.

**Проверка структуры графика — механическая, не «посмотреть глазами».**
Визуальные критерии — самый слабый класс проверок в программе (то же
признано для дашбордов Power BI, `design/decisions.md`); там, где можно
не полагаться на взгляд, программа не полагается. Свойства из критерия
B5 — число осей, подписи, единицы, легенда, тип осей — читаются из
объекта `Figure` тем же кодом, что его построил:

```python
def check(fig) -> bool:
    ok = True
    for ax in fig.axes:
        if ax.name != "rectilinear":
            print("недопустимый тип осей (3D?):", ax.name); ok = False
        if not ax.get_ylabel() or "грн" not in ax.get_ylabel():
            print("нет единиц на оси Y:", repr(ax.get_ylabel())); ok = False
        if ax.get_legend() is None:
            print("нет легенды:", repr(ax.get_ylabel())); ok = False
    if not fig.axes[-1].get_xlabel():
        print("нет подписи оси X"); ok = False
    return ok
```

На варианте с двумя подграфиками — `True`. На варианте с одной общей осью
эта же функция пропустила бы обе линии молча: подписи и легенда у него
тоже есть, проверка структуры не видит, что график вводит в заблуждение
масштабом — это видно только числом (0.34%) или взглядом.

## 1.6. Типичные ошибки

Обе измерены на этом датасете.

**Ошибка:** строите оба ряда на одной оси Y — «это же один график, зачем
два».
**Почему выглядит правильно:** обе оси подписаны, легенда есть, ничего не
падает — формальные признаки критерия B5 выполнены.
**Почему неправильно:** диапазон оси — от −945 103 до 30 189 768 грн, а
ряд комиссии (470 118…576 893) занимает **0.34%** высоты. График
технически корректен и содержательно бесполезен: по нему нельзя увидеть
ни рост, ни падение комиссии, только то, что она маленькая на фоне
оборота.
**Как правильно:** два подграфика с общей осью X, каждый в своём
масштабе, как в 1.3.

**Ошибка:** чините масштаб через `ax.twinx()` — вторую ось Y с другим
диапазоном на том же холсте.
**Почему выглядит правильно:** обе линии видны целиком, ни одна не
превращается в плоскую черту, единицы можно подписать раздельно у каждой
оси.
**Почему неправильно:** программа запрещает этот же приём для дашбордов
Power BI (P3, критерий 13, `design/decisions.md`) по названной там
причине — масштаб каждой оси выбирается независимо и произвольно, и
совпадение или расхождение форм двух линий на графике с двойной осью
ничего не говорит о реальной связи рядов: тот же график с другим
пределом правой оси нарисует любую форму совмещения, какую попросят.
**Как правильно:** раздельные подграфики с общей осью X — форма каждого
ряда видна без риска, что она подстроена выбором диапазона второй оси.

## 1.8. Вопрос уровня собеседования

**Вопрос:** «Коллега предлагает наложить оборот и комиссию на один график
с двумя осями Y — одна слева, другая справа, — чтобы уместить оба ряда на
одном холсте. Согласны?»

**Эталон (ответ покрывает ≥3 из 4 пунктов):**
1. Называет главный риск: масштаб каждой оси выбирается независимо, и
   совмещение двух рядов на двойной оси может нарисовать корреляцию,
   которой нет, или спрятать реальную — форма совпадения линий зависит от
   выбора пределов осей, а не только от данных.
2. Предлагает конкретную альтернативу: два подграфика с общей осью X,
   каждый со своей осью Y — форма каждого ряда видна отдельно, без
   совмещения шкал.
3. Отмечает, что то же правило уже действует в программе для дашбордов
   Power BI (запрет двойных осей, критерий 13 P3) — решение не
   специфично для matplotlib, это общий принцип показа данных.
4. Указывает, что на одной **общей** оси (без второй шкалы вовсе) те же
   два ряда становятся нечитаемыми в другую сторону — меньший ряд прячется
   у нуля, — и называет измеренную величину (доля высоты графика) как
   способ проверить это, а не полагаться на взгляд.
