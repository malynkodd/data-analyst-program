# Данные проекта P6 («Заказчик передумал»)

## Статус этого файла

Полная декларация — `program/P6/step-00.md`. Данные — **реальные
публичные**, зафиксированные снапшотом (часть 5 blueprint, «Реальные
публичные данные — P3, P4, P6»), не синтетика.

**Снапшот коммитится в репозиторий, а не генерируется заново** — та же
конвенция, что у П3: Держстат SDMX и API НБУ — живые потоки без
версионирования, повторный запрос вернёт другие числа. `fetch_stat.py`
и `fetch_nbu.py` — инструмент выгрузки, не генератор для CI.

**`robots.txt` не блокирует ни один источник** (решение 36,
`design/decisions.md`; проверено `stat.gov.ua/robots.txt` 2026-08-22 —
только общий `User-agent: *`, никаких именных AI-блоков; `bank.gov.ua`
проверен ещё в П3). Снапшот выгружен агентом напрямую тем же способом,
что П3 — `urllib.request` из Bash, не `WebFetch` (§9,
`research/sources-gate.md` — `WebFetch` обрубает контент заметно ниже
объёма любого из этих файлов).

**Найденный дефект источника (не в описании blueprint):** запрос
`all/all` без нарезки по ключу на потоке
`DF_EXTERNAL_TRADE_INDIVIDUAL_GOODS_BY_COUNTRIES` не отвечает —
измерено прогоном 2026-08-22, 40 с, обрыв соединения без единого байта
тела ответа (тот же класс, что раньше зафиксировала §4
`research/sources-gate.md` на соседнем потоке: 500 через 30 с). Причина
— размерный перекрёсток 22855 кодов `GOODS` × ~270 кодов `AREA`.
Решение — нарезка по ключу: один код `GOODS` (`126400000000` = Группа
64, обувь), `AREA=_T` (в целом) — ответ падает до 37 КБ, 0.9 с.
`fetch_stat.py` воспроизводит отрицательный пример перед выгрузкой.
