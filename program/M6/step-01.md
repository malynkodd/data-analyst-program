## 1.2. Теория своими словами

**Деньги целым числом копеек — обычный формат API, не ошибка выгрузки.**
Большинство платёжных API (в том числе крупные эквайеры) отдают суммы в
минимальных единицах валюты — копейках, центах — именно чтобы не иметь
дела с плавающей точкой при передаче денег. Колонка называется
`amount_cents`, и это не подсказка «раздели на 100 из вежливости», а
контракт: значение читается только вместе с единицей измерения, которая
записана в самом имени колонки.

**Unix-время — число секунд от 1970-01-01 UTC.**
[`pandas.to_datetime`](https://pandas.pydata.org/docs/reference/api/pandas.to_datetime.html)
разбирает его параметром `unit="s"`: без этого параметра число читается
как дата в наносекундах и даёт результат в районе 1970 года, а не 2026.

## 1.3. Разобранный пример на сквозном датасете

Прогон на машине автора 2026-08-20, pandas 3.0.5.

```python
import pandas as pd

ledger = pd.read_csv("raw/ledger.csv", dtype={"txn_id": "string", "account_id": "string"})
ledger["ts"] = pd.to_datetime(ledger["ts"])

settlement = pd.read_csv("raw/settlement.csv",
                         dtype={"settlement_id": "string", "ledger_txn_id": "string"})
settlement["amount"] = settlement["amount_cents"] / 100
settlement["fee"] = settlement["fee_cents"] / 100
settlement["settled_date"] = pd.to_datetime(settlement["settled_ts"], unit="s").dt.date
```

```
леджер: 2324 строки, 6 колонок
расчёт: 2204 строки, 5 колонок (плюс amount, fee, settled_date после конверсии)
```

**Первый проход сверки — точный по ключу, без причин.** Для каждой
операции со статусом `completed` в леджере проверяется, есть ли **хоть
одна** строка расчёта с таким же `ledger_txn_id`:

```python
completed = ledger[ledger["status"] == "completed"]
settled_ids = set(settlement["ledger_txn_id"])
matched = completed["txn_id"].isin(settled_ids)
```

```
completed-операций: 2047
из них есть расчёт: 1996
из них расчёта нет: 51
```

**Расчёты без основания.** Отдельно, независимо от статуса операции,
считаются строки `settlement.csv`, чей `ledger_txn_id` не встречается в
леджере вовсе — не потому, что операция другого статуса, а потому, что
такой операции нет:

```python
ledger_ids = set(ledger["txn_id"])
orphans = settlement[~settlement["ledger_txn_id"].isin(ledger_ids)]
```

```
расчётов без основания в леджере: 15
```

51 и 15 — это ещё не диагноз, а факт: сверка на этом шаге не объясняет
причины, это работа `step-02.md`. Здесь важно, что числа верны, а не
почему они такие.

## 1.6. Типичные ошибки

Обе измерены на этом датасете.

**Ошибка:** читаете `amount_cents` как деньги без деления на 100.
**Почему выглядит правильно:** колонка числовая, `pd.read_csv` не
падает, сумма считается.
**Почему неправильно:** сумма всех расчётов — **336 426 910** вместо
**3 364 269.10** грн — ровно в 100 раз больше. Разница не бросается в
глаза на одной строке (33388 против 333.88 — оба похожи на деньги), но
видна на сумме или на любом отдельном значении сверх типичного чека
счёта (400–7000 грн): 33388 «грн» за одну операцию — это уже подозрительно,
но ничего не падает и не предупреждает.
**Как правильно:** `amount_cents / 100`, деление — часть чтения, а не
опциональный шаг для «красивого вида».

**Ошибка:** читаете `settled_ts` без `unit="s"`.
**Почему выглядит правильно:** `pd.to_datetime` не падает и возвращает
колонку типа `datetime64`.
**Почему неправильно:** `1767258000` без `unit="s"` разбирается как
наносекунды от начала эпохи — результат **1970-01-21**, а не 2026 год;
все 2204 расчёта окажутся в одном и том же январе 1970 года.
**Как правильно:** `pd.to_datetime(settlement["settled_ts"], unit="s")`.
Проверка — год результата: 2026, не 1970.

## 1.8. Вопрос уровня собеседования

**Вопрос:** «В выгрузке от платёжного провайдера сумма операции —
`33388`. Как узнать, это 333.88 грн или 33 388 грн, если в документации
API не заглянуть прямо сейчас?»

**Эталон (ответ покрывает ≥3 из 4 пунктов):**
1. Смотрит на имя колонки в самой выгрузке — `amount_cents` называет
   единицу прямо, и это первое, что стоит проверить, а не гадать.
2. Сравнивает с порядком величины уже известных сумм того же счёта или
   домена — если типичная операция около 1000 грн, а прочитанное число
   в 100 раз больше или меньше, единица, скорее всего, не та.
3. Проверяет на одной операции, значение которой известно из другого
   источника (леджер, скриншот, счёт), а не доверяет всей колонке сразу.
4. Называет источник правды при расхождении: контракт API — то, что
   документировано, а не то, что выглядит правдоподобно на глаз.
