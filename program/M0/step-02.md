# M0.2. Смотрит, считает и ищет в csv через готовые скрипты, не открывая Excel

Умение: I2 (задачи 4–6 из 6: «смотрит первые 20 строк csv без Excel,
считает строки в файле, находит строку по подстроке — через
предоставленные скрипты, решение 13»; задачи 1–3 закрыты в `step-01.md`)
Модуль: M0
Требуется до этого: `step-01.md` (запуск скрипта — тот же механизм, здесь
применяется к другим скриптам)
Время: 3–3.5 ч (оценка проектная, не измерена; калибровка —
`research/self.md`)

## 1.1. Цель и связь с умением

После шага вы можете быстро посмотреть первые строки большого csv,
посчитать, сколько в нём строк (в целом и по условию), и найти строки по
подстроке — не открывая файл в Excel и не читая его целиком глазами. Это
последние три из шести задач I2; решение 13 (`design/decisions.md`)
явно требует, чтобы эти три задачи выполнялись через предоставленные
кросс-платформенные скрипты, а не через `head`/`wc`/`grep`, которых нет в
стандартной Windows PowerShell без WSL/Git Bash.

## 1.2. Теория своими словами

Открывать csv в Excel, чтобы просто посмотреть, что внутри, — не всегда
правильный инструмент, даже для того, кто хорошо знает Excel (сам Excel —
предмет M2, следующего модуля). Три причины:

1. **Скорость.** Excel запускается и парсит файл на большом объёме
   заметно дольше, чем скрипт печатает первые несколько строк.
2. **Точный подсчёт.** «Сколько строк в файле» в Excel требует прокрутки
   до конца или отдельной формулы; скрипт печатает число сразу.
3. **Поиск без открытия.** Если нужно только проверить, есть ли в файле
   хоть одна строка с конкретным словом, открывать программу для
   просмотра таблиц ради этого не нужно.

Рыночная цитата практикующего аналитика — «if a csv is borked… I use
vim» [М, «Мифы (б)»] — обоснование самого умения I2 (часть 1 blueprint):
терминальные инструменты для быстрой диагностики файла — рыночный сигнал,
не прихоть. Решение 13 переносит это на скрипты вместо конкретных команд
UNIX-шелла (`grep`, `head`, `wc`) — эффект тот же, набор команд другой, и
он не зависит от того, запускаете вы скрипт из PowerShell или из Git Bash
(платформа программы — Windows, решение 21 `design/decisions.md`).


**Справочник по тому, что здесь используется.** Текст шага объясняет
только нужное для задания; полное описание команд и параметров — в
официальной документации:

- [Перемещение по каталогам в PowerShell](https://learn.microsoft.com/en-us/powershell/scripting/samples/managing-current-location)

## 1.3. Разобранный пример на сквозном датасете

Датасет — `program/M0/data/orders_log.csv`, 500 строк, описан в
`data/README.md`. Три готовых скрипта: `view_head.py`, `count_lines.py`,
`find_row.py`.

Первые строки без открытия файла целиком:

```
$ python3 view_head.py orders_log.csv
order_id,order_date,city,status,note
D0001,2026-06-27,Odesa,shipped,delivered on time
D0002,2026-06-28,Kharkiv,shipped,delivered on time
D0003,2026-07-24,Odesa,shipped,delivered on time
D0004,2026-07-09,Dnipro,shipped,delivered on time
...
```

(по умолчанию печатаются первые 20 строк файла, считая строку заголовка;
здесь показаны первые 5 для примера — полный вывод длиннее).

Сколько всего строк данных, и сколько из них — определённого статуса:

```
$ python3 count_lines.py orders_log.csv
rows in file: 500

$ python3 count_lines.py orders_log.csv --status shipped
rows in file: 500
rows with status == shipped: 304
```

Поиск по подстроке — не по имени колонки, а по содержимому любой из них:

```
$ python3 find_row.py orders_log.csv --contains damaged --limit 3
D0008,2026-06-28,Kyiv,shipped,packaging damaged
D0019,2026-05-12,Lviv,shipped,packaging damaged
D0040,2026-06-07,Dnipro,shipped,packaging damaged
total matches: 47
```

`--limit 3` ограничивает, сколько строк напечатать; `total matches: 47`
печатается всегда, независимо от `--limit` — это число не зависит от
того, сколько строк вы решили увидеть.

## 1.4. Задание

На том же `orders_log.csv`, не подглядывая в `data/reference_answers.md`
до того, как получите число сами:

1. `view_head.py orders_log.csv --lines 8` — посмотрите первые 8 строк.
2. `count_lines.py orders_log.csv --status pending` и отдельно
   `count_lines.py orders_log.csv --status cancelled` — запишите оба
   числа.
3. Проверьте арифметику: `shipped` (304, из примера в 1.3) + ваш `pending`
   + ваш `cancelled` должно дать ровно 500 (общее число строк файла).
4. `find_row.py orders_log.csv --contains "out of stock" --limit 3` и
   `find_row.py orders_log.csv --contains Lviv --limit 5` — запишите оба
   `total matches`.
5. Сверьте все 4 записанных числа (`pending`, `cancelled`, `out of stock`,
   `Lviv`) с `data/reference_answers.md` — только после того, как
   получили их сами.

## 1.5. Критерий готовности

- Все 3 команды из задания выполнены без ошибок интерпретатора.
- Сумма `shipped` + ваш `pending` + ваш `cancelled` = 500, расхождение 0.
- Число `total matches` для `"out of stock"` и для `Lviv` совпадает с
  `data/reference_answers.md` (22 и 62 соответственно), расхождение 0.
- 3 задачи из 3 выполнены без подсказки — вместе с двумя задачами
  `step-01.md` это закрывает все 6 задач I2.
- Уложились в ≤35 минут.

## 1.6. Типичные ошибки

**Ошибка:** запускает `count_lines.py orders_log.csv --status Pending` (с
заглавной буквы) и получает 0 вместо 117.
**Почему выглядит правильно:** «Pending» и «pending» выглядят как одно и
то же значение статуса.
**Почему неправильно:** сравнение в скрипте регистрозависимое — колонка
`status` в файле хранит значения строго строчными буквами (`pending`, не
`Pending`); при несовпадении регистра ни одна строка не подходит под
условие, и результат — 0, а не «файл повреждён» или «скрипт не работает».
**Как правильно:** вводить значение фильтра ровно так, как оно записано в
данных — строчными буквами.

**Ошибка:** после `find_row.py orders_log.csv --contains "out of stock"
--limit 3` видит 3 напечатанные строки и делает вывод «в файле 3
совпадения».
**Почему выглядит правильно:** это единственные строки, которые скрипт
показал.
**Почему неправильно:** `--limit` управляет только тем, сколько строк
напечатать на экран; фактическое число совпадений — `total matches: 22`,
и оно печатается отдельной строкой всегда, вне зависимости от `--limit`.
**Как правильно:** для количества совпадений смотреть на `total
matches`, а не считать напечатанные строки.

**Ошибка:** ищет подстроку `--contains stock` вместо `--contains "out of
stock"` (без кавычек, с пробелами внутри значения).
**Почему выглядит правильно:** слово «stock» — часть искомой фразы,
кажется, что более короткий запрос найдёт не меньше строк.
**Почему неправильно:** `--contains stock` находит те же 22 строки (слово
`stock` встречается только в фразе «out of stock» в этом датасете), но
без кавычек значение с пробелом «out of stock» терминал разобьёт на
несколько отдельных аргументов, и скрипт получит только `--contains out`
— упадёт с ошибкой аргументов, а не найдёт частичное совпадение.
**Как правильно:** значения с пробелами всегда брать в кавычки — `"out of
stock"`, а не `out of stock` без них.

**Ошибка:** считает, что `view_head.py` без флага `--lines` показывает
все строки файла, раз он не написал, сколько именно.
**Почему выглядит правильно:** файл небольшой (500 строк + заголовок),
кажется естественным, что скрипт покажет всё.
**Почему неправильно:** по умолчанию `--lines` равен 20 — печатаются
первые 20 строк (включая заголовок), остальные 480 строк файла не
показаны и не будут показаны без явного увеличения `--lines`.
**Как правильно:** для просмотра большего диапазона задавать `--lines`
явно; для точного числа всех строк — `count_lines.py`, а не подсчёт
глазами напечатанного.

## 1.8. Вопрос уровня собеседования

**Вопрос:** «Вам прислали csv на 2 миллиона строк и просят быстро
сказать, сколько в нём заказов с конкретным статусом. Что вы сделаете?»

**Эталон (ответ покрывает ≥3 из 4 пунктов):**
1. Не открывает файл в Excel/Google Sheets целиком — на таком объёме это
   либо не сработает, либо займёт заметное время только на загрузку.
2. Использует построчный или потоковый инструмент (скрипт, командную
   утилиту) для подсчёта по условию, не читая весь файл в память сразу
   как таблицу.
3. Сначала смотрит на первые несколько строк, чтобы понять структуру
   (названия колонок, формат значения статуса — регистр, пробелы), и
   только потом считает.
4. Отдельно проверяет регистр и точное написание искомого значения —
   называет это как источник частой ошибки (пункт 1 «типичных ошибок»
   этого шага).
