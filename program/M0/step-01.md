# M0.1. Работает в терминале: переходит в каталог, запускает скрипт, создаёт файл в UTF-8

Умение: I2 (задачи 1–3 из 6: «переходит в каталог, запускает готовый
скрипт, создаёт и правит текстовый файл в рабочей папке, сохраняет в
UTF-8»; выбор редактора умением не проверяется и остаётся за вами;
задачи 4–6 — в `step-02.md`)
Модуль: M0
Требуется до этого: —
Время: 2.5–3 ч (оценка проектная, не измерена; калибровка —
`research/self.md`)

## 1.1. Цель и связь с умением

После шага вы умеете открыть терминал, перейти в нужную папку, запустить
готовый Python-скрипт и создать в этой же папке текстовый файл, который
после сохранения остаётся читаемым — не превращается в «кракозябры» из-за
неверной кодировки. Это первые три из шести задач I2. Остальные три —
просмотр, счёт и поиск по csv через готовые скрипты — в `step-02.md`, на
том же датасете.

## 1.2. Теория своими словами

Терминал — программа, которая принимает текстовые команды вместо кликов
мышью. На этом шаге от неё нужны три вещи.

1. **Переход в каталог.** Терминал всегда «стоит» в какой-то одной папке —
   рабочей директории. Команда `cd путь/до/папки` переходит в неё; без
   перехода команды, ссылающиеся на файл по имени (не по полному пути),
   его не найдут.
2. **Запуск скрипта.** `python3 script.py` (или `python script.py`, если
   команда `python3` не установлена — какая именно есть на вашей системе,
   вы уже проверили при установке Python) запускает готовый файл с кодом.
   Вы не пишете код в этом шаге — это предмет модуля M5 (Python). Вы
   запускаете то, что уже написано, и читаете, что оно печатает.
3. **Кодировка UTF-8.** Текстовый файл — это байты на диске плюс
   договорённость о том, какие байты каким символам соответствуют.
   UTF-8 — та договорённость, что одинаково работает для кириллицы и
   латиницы; другой эта программа не использует. Здесь легко ошибиться:
   редактор сохранил файл в Windows-1251, а прочитали его как UTF-8 — и
   вместо кириллицы на экране нечитаемый набор символов. Сам файл при
   этом цел; сломана только договорённость. Попадаются такие файлы чаще,
   чем кажется: «if a csv is borked… I use vim» [М, «Мифы (б)»] — цитата
   практикующего аналитика ровно про них.

Редактор берите любой — Блокнот, VS Code, что уже стоит. Жёсткое
требование одно: файл сохраняется в UTF-8. Современные редакторы так и
делают по умолчанию. Если ваш спрашивает кодировку явно — UTF-8, не
«ANSI» и не «Windows-1251».

Кодировка терминала — отдельная история от кодировки файла, и их легко
спутать. Файл на диске может быть безупречным UTF-8, а терминал всё
равно покажет не то: старый `cmd.exe` без `chcp 65001` гонит вывод через
свою кодовую страницу (cp866/cp1251) вместо UTF-8, и вместо букв на
экране вопросительные знаки или пустые квадраты. Отложить это на потом
не выйдет. Начиная с M2 шаги печатают в терминал живой украиноязычный
текст — названия товаров, контрагентов, — и транслитерацией в ASCII
задача больше не обходится (`design/decisions.md`, решение 17). Поэтому
терминал проверяется один раз и здесь, в M0, а не на том шаге, где он
впервые всё сломает.


**Справочник по тому, что здесь используется.** Текст шага объясняет
только нужное для задания; полное описание команд и параметров — в
официальной документации:

- [Запуск Python из терминала](https://docs.python.org/3/tutorial/interpreter.html)
- [Перемещение по каталогам в PowerShell](https://learn.microsoft.com/en-us/powershell/scripting/samples/managing-current-location)
- [Стандартные кодировки Python — где искать `cp1251` и `utf-8`](https://docs.python.org/3/library/codecs.html#standard-encodings)

## 1.3. Разобранный пример на сквозном датасете

Датасет модуля — `program/M0/data/`, описан в `data/README.md`. В этом
шаге сам `orders_log.csv` не используется (это `step-02.md`) — здесь
пример работает с двумя вспомогательными скриптами той же папки:
`check_env.py` и `check_utf8.py`.

Переходим в папку с данными и запускаем первый скрипт:

```
$ cd program/M0/data
$ python3 check_env.py --name Danylo
python: 3.11.9
cwd: D:\data-analyst-program\program\M0\data
hello, Danylo
```

Скрипт не открыл ничего кроме себя самого: он напечатал версию Python,
текущую рабочую папку и подставил переданное имя. Если вместо этого
терминал печатает `command not found` или `'python3' is not recognized`
— команда на вашей системе называется иначе (`python` вместо `python3`,
или наоборот); проверьте, что дало вам при установке.

Дальше создаём текстовый файл прямо в этой рабочей папке — любым
редактором, лишь бы сохранить в UTF-8. Файл `sample_ok.md`:

```
Мой дневник

Сегодня прошёл базовые команды терминала.
Осталось разобраться с git.
```

Проверяем результат готовым скриптом, не открывая файл повторно на
глаз — критерий должен быть механическим, а не «на вид нормально»:

```
$ python3 check_utf8.py sample_ok.md
decoded as UTF-8: yes
non-empty lines: 3
contains non-ASCII characters: True
OK
```

`contains non-ASCII characters: True` — это подтверждение, что кириллица
не потерялась: в файле есть символы за пределами ASCII (латиница, цифры,
базовая пунктуация), и они прочитались. Если тот же текст сохранить в
кодировке Windows-1251 (эффект такой, будто редактор сохранил не в
UTF-8), результат другой:

```
$ python3 check_utf8.py sample_bad.md
FAIL: file is not valid UTF-8 ('utf-8' codec can't decode byte 0xc4 in position 0: invalid continuation byte)
```

Скрипт не «ругается на кириллицу вообще» — он ругается на конкретный
байт, который не собирается в валидный UTF-8. Разница между `OK` и
`FAIL` тут не про то, что написано в файле, а про то, в какой кодировке
он лёг на диск.

Отдельно, теперь про сам терминал — не про файл — запускаем
`check_console.py`:

```
$ python3 check_console.py
Проверка кодировки: яжщч, ґєіїу, №12345
```

Сверяем построчно с эталонной строкой выше в этом файле:
`Проверка кодировки: яжщч, ґєіїу, №12345`. Совпадает посимвольно — терминал
настроен верно. Если вместо кириллицы — вопросительные знаки, квадраты
или `?` вместо каждой буквы — терминал показывает не то, что напечатал
скрипт, и нужно почитать раздел 1.6 «Типичные ошибки» этого шага.

## 1.4. Задание

В рабочей папке `program/M0/data/` (или в любой другой папке — местоположение
не проверяется, важна сама последовательность действий):

1. Запустите `check_env.py` без флага `--name` и отдельно — с флагом
   `--name`, подставив своё имя.
2. Создайте текстовый файл `diary.md` любым редактором. Содержимое —
   ваше: минимум 3 непустых строки, минимум одна строка — на русском
   (с кириллицей). Сохраните файл в UTF-8.
3. Отредактируйте файл: допишите ещё одну строку (файл должен остаться
   тем же самым — допишите в него и пересохраните, не заводите второй).
4. Проверьте результат: `python3 check_utf8.py diary.md --min-lines 4`.
5. Запустите `check_console.py` и сверьте вывод с эталонной строкой из
   раздела 1.3 посимвольно.

## 1.5. Критерий готовности

- `check_env.py` запущен дважды (с флагом и без), оба раза без ошибки
  интерпретатора.
- `check_utf8.py diary.md --min-lines 4` печатает `decoded as UTF-8: yes`
  и заканчивается строкой `OK` (код выхода 0, не `FAIL`).
- В выводе `check_utf8.py` строка `contains non-ASCII characters: True`.
- `non-empty lines` ≥ 4 (3 из первой версии файла + минимум 1 после
  правки).
- Вывод `check_console.py` совпадает посимвольно с эталонной строкой
  `Проверка кодировки: яжщч, ґєіїу, №12345` из раздела 1.3.
- Уложились в ≤30 минут.

Проверяете сами: `check_utf8.py` возвращает `OK`/`FAIL` и код выхода —
бинарный результат, суждение не нужно.

**Не сошлось — не переделывайте вслепую:** раздел 1.6 разбирает 4 ошибки
этого шага, каждую с признаком, по которому её видно в своём результате.

## 1.6. Типичные ошибки

**Ошибка:** сохраняете файл в кодировке по умолчанию старого редактора
(«ANSI» в Блокноте на русской локали Windows — это Windows-1251, не
UTF-8).
**Почему выглядит правильно:** в самом редакторе кириллица на экране
целая. Он читает файл той же кодировкой, которой его записал, и
расхождения не видно.
**Почему неправильно:** `check_utf8.py` открывает не ваш редактор, а
байты, и декодирует их как UTF-8. На файле в Windows-1251 получается
`FAIL: file is not valid UTF-8 ('utf-8' codec can't decode byte 0xc4 in
position 0: invalid continuation byte)` — указан конкретный байт и
конкретная позиция, а не общая жалоба на файл.
**Как правильно:** если редактор спрашивает кодировку при сохранении —
выбирать UTF-8. Если не спрашивает, скорее всего он и так пишет UTF-8:
так делают VS Code, Notepad++ и Блокнот Windows 10+.

**Ошибка:** создаёте новый файл под другим именем на шаге «отредактируйте
файл» вместо правки существующего.
**Почему выглядит правильно:** итоговое содержимое может быть тем же
самым текстом.
**Почему неправильно:** критерий явно требует правки существующего
`diary.md` — при создании нового файла вместо него команда
`check_utf8.py diary.md` либо не найдёт файл (`FileNotFoundError`), либо
проверит старую, ещё не отредактированную версию с 3 строками, а не 4.
**Как правильно:** открыть тот же `diary.md`, дописать строку, сохранить
тем же именем.

**Ошибка:** `check_console.py` печатает вопросительные знаки или пустые
квадраты вместо кириллицы, хотя сам скрипт не менялся.
**Почему выглядит правильно:** скрипт отработал и что-то напечатал.
Нет `Traceback` — значит, всё в порядке; так это и читается.
**Почему неправильно:** Python здесь ни при чём. `check_console.py`
принудительно выставляет вывод в UTF-8 (`sys.stdout.reconfigure`), то
есть до терминала дошли корректные байты. Ломается последний шаг —
рендер: активная кодовая страница терминала не UTF-8.
**Как правильно:** в `cmd.exe` — выполнить `chcp 65001` и перезапустить
скрипт в том же окне; либо перейти на терминал, который по умолчанию
работает в UTF-8 (Windows Terminal, PowerShell 7, встроенный терминал
VS Code, Git Bash) — на них шаг не потребует ручной настройки вовсе.
Проверка — тот же `check_console.py`, а не «на глаз стало красивее».

**Ошибка:** запускаете `check_env.py` не из той папки, где он лежит, и
получаете `can't open file 'check_env.py': No such file or directory`.
**Почему выглядит правильно:** команда набрана без единой опечатки.
**Почему неправильно:** терминал ищет `check_env.py` в текущей рабочей
папке. Не перешли в `program/M0/data/` командой `cd` — скрипта для него
там нет. Сломан не скрипт, а место, где стоит терминал.
**Как правильно:** сначала `cd` в папку со скриптом, потом запуск. Либо
указать полный путь к файлу — второй рабочий способ.

шаг программы, и здесь такое время закладывается честно.

## 1.8. Вопрос уровня собеседования

**Вопрос:** «Коллега прислал скрипт и говорит: у меня работает, а на
твоей машине — нет. Что вы проверите первым?»

**Эталон (ответ покрывает ≥3 из 4 пунктов):**
1. Версию интерпретатора (Python и её отличие от версии коллеги).
2. Рабочую папку, из которой запускается скрипт (тот же файл, тот же
   относительный путь до данных).
3. Кодировку файлов, которые скрипт читает или создаёт (частая причина
   расхождения на Windows).
4. Не сравнивает вывод на глаз, а печатает у себя те же диагностические
   значения (версия, cwd), что и коллега, и сравнивает построчно.
