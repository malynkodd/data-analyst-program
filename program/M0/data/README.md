# Сквозной датасет модуля M0

Синтетика. Используется без изменений во всех трёх шагах M0 (M0.1–M0.3) —
правило части 1.3 скилла curriculum-design: один датасет на модуль,
объявлен один раз в `step-00.md`, не меняется между шагами.

Категория (часть 1.3 curriculum-design): **сквозной модуль вне проектной
привязки** — синтетика по умолчанию, третья категория, добавленная в
скилл при пилоте M1. M0 не ведёт напрямую ни к одному из P1–P6 — он даёт
умения (I2 и фрагмент I1), нужные перед M1 и перед каждым проектом с
кодом (часть 3.1/3.2 blueprint).

Все команды в шагах M0 — только вызовы предоставленных Python-скриптов
или самого `git` (решение 13, `design/decisions.md`): никаких
`grep`/`awk`/`sed`/`head`/`wc`/`stat` как отдельных POSIX-инструментов.

## Файлы

| Файл | Роль |
|---|---|
| `generate_orders_log.py` | Генератор `orders_log.csv`. Детерминирован: `SEED = 20260801`, `REFERENCE_DATE = 2026-08-01`. Перегенерация даёт побайтово тот же файл. |
| `orders_log.csv` | 500 строк, эталон для критериев готовности `step-02.md`. |
| `check_env.py` | Печатает версию Python и рабочую папку — первый скрипт, который учащийся запускает (`step-01.md`, задача 2 умения I2). |
| `view_head.py` | Печатает первые N строк файла (по умолчанию 20) — замена `head` (`step-02.md`, задача 4). |
| `count_lines.py` | Считает строки данных, с опциональным фильтром `--status` — замена `wc -l` (`step-02.md`, задача 5). |
| `find_row.py` | Находит строки, где есть подстрока — замена `grep` (`step-02.md`, задача 6). |
| `check_utf8.py` | Проверяет текстовый файл, который учащийся создаёт сам: декодируется ли как UTF-8, сколько непустых строк, есть ли не-ASCII символы (`step-01.md`, задача 3). |
| `reference_answers.md` | Предвычисленные контрольные числа. |

Датасет намеренно "чистый" — без разных форматов дат, без текстовых
чисел, без дублей написания. M0 учит пользоваться терминалом, а не искать
дефекты в данных: последнее — предмет M2 и M6.

## Схема `orders_log.csv`

| Колонка | Смысл | Значения |
|---|---|---|
| `order_id` | Идентификатор заказа | `D0001`…`D0500` |
| `order_date` | Дата заказа | ISO, 0–120 дней до `REFERENCE_DATE` |
| `city` | Город доставки | 8 городов Украины, латиницей (см. довод про ASCII-вывод ниже) |
| `status` | Статус заказа | `shipped` / `pending` / `cancelled` |
| `note` | Примечание | зависит от статуса, см. ниже |

## Почему значения латиницей, а не кириллицей

Часть скриптов модуля (`find_row.py`, `count_lines.py`) печатает строки
датасета в консоль целиком. Кириллица в stdout ломается на части
Windows-терминалов из-за консольной кодовой страницы (cp866/cp1251) — тот
же довод, что в `program/M1/data/count_active.py`. Кириллица в модуле
всё же используется — в текстовом файле, который учащийся создаёт сам в
`step-01.md` (задача 3, проверяется `check_utf8.py`), но этот файл не
печатается скриптом целиком, только его статус (декодировался/нет, сколько
строк, есть ли не-ASCII символы).

## Почему без sha256 и без снапшота

Правило снапшота (файл + дата выгрузки + sha256, часть 5 blueprint)
относится к реальным источникам (P3, P4, P6). Здесь датасет
синтетический — эталон фиксируется генератором с зашитым `SEED`.
