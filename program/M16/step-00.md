# M16.00. Декларация модуля (умения, датасет, предусловие)

Не шаг для учащегося — служебный файл, требуемый разделом 1.3 скилла
curriculum-design. Команд не содержит (решение 20 `design/decisions.md`).

## Отступление от конвенции модуля: два наложенных ограничения

**Первое — то же, что у M7 (`program/M7/step-00.md`): нет доступа к
самому инструменту.** Looker Studio — веб-приложение с GUI, агент не
может его открыть. Разница с M15 (Tableau) в источнике целевых чисел:
здесь эталон — не готовое число из прошлого гейта, а **самосогласованность**:
датасет M7 генерируется `RAND()` без фиксированного seed (решение 29
сознательно не требует детерминизма там, где движок сам считает объём и
оплату) — то есть у C4 нет и не может быть заранее известного правильного
числа. Критерий C4 («цифры сходятся с SQL») от этого не слабее: он
сравнивает отчёт не с записанным в репозитории эталоном, а с SQL-запросом,
который учащийся выполнит сам на своей копии таблицы M7.

**Второе — найдено этим заходом, до написания шага: Looker Studio требует
Google Cloud Billing account для подключения к BigQuery, а M7 намеренно
обошёлся без него.** Решение — `design/decisions.md`, решение 34: M16
включает биллинг в том же GCP-проекте и остаётся в бесплатном уровне
(10 GiB хранения, 1 TiB запросов/месяц); M7 не меняется. Читать решение
34 целиком — там источники и оценка риска.

**Третье, найдено при отладке проверки: живость публичной ссылки нельзя
проверить HTTP-запросом.** Испробовано и отброшено: `lookerstudio.
google.com` отвечает HTTP 200 и на настоящий пример отчёта из
документации Google, и на заведомо несуществующий `/reporting/00000000-…`
— оба редиректят на общую страницу без браузерной сессии. Различить
скриптом нельзя; открытие ссылки — самопроверка, как H1/H3 в M12.
`DEFERRED.md`, раздел «Проверка публичной ссылки Looker Studio».

## Часовой бюджет

Один шаг, 4–6 ч — совпадает с вилкой части 6.1 blueprint (4–6 ч) по
обеим границам. Не подгонка (решение 24 в узком смысле не применяется:
здесь один шаг равен модулю, подгонять сумму нечем) — вилка и оценка
шага заданы одним и тем же числом с самого начала, потому что раскладки
не было.

## Датасет — таблица M7, без изменений

У M16 нет своего генератора: источник — та самая таблица `transactions`
(4 386 000 строк, 7 колонок), которую `M7/step-01.md` создал SQL-запросом
внутри BigQuery. Единственное новое действие с данными — включение
billing на проекте (решение 34); сама таблица не пересоздаётся и не
меняется.
