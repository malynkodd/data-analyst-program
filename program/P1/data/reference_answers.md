# Эталонные ответы P1 (сеть из 12 магазинов)

Считает `reference_p1.py`, независимо от списков `generate_p1.py`
(правило двойного авторства, скилл `curriculum-design`, раздел 1.3).

## Контрольная точка

Прогнать до решения задач проекта:

```
> python program\P1\data\generate_p1.py
```

Ожидается:

```
sales_transactions.csv: 57619 строк, sha256 4c3ad3f26b485b235f8ea6f9d93e6eee4c36c6837fda7f56cc00db4e8ed53d48
```

Расхождение хотя бы в одном символе — датасет собран не тем генератором
или не той версией Python (`random.seed(20260821)` фиксирован до первого
обращения к `random`); дальше сверять нечего.

## Разбор закрыт турникетом

Ответы, ранги, выбранные трактовки и разбор дефектов вынесены в
`answers.md` и закрыты турникетом (`tools/vault.py`, решения 51 и 53).
Причина названа независимой проверкой
`audit/independent-final-check-2026-08-24.md`, блокер 8.2: проект — это
единственное доказательство, что умения работают вместе, и приёмка, где
ответ лежит рядом открытым файлом, доказывает только умение читать.

Открывается после сохранённой попытки, проход пишется в
`research/attempts.md`:

```
> python tools\vault.py open program\P1\data\answers.md --attempt program\P1\work\<ваш файл>
```

Открытым здесь остаётся ровно то, без чего проект не начать: контрольная
точка датасета выше.

**`ref_by_store.csv` тоже закрыт** — в этом проекте эталонная таблица
и есть ответ на вопрос заказчика, и держать её открытой значило бы
закрыть разбор, оставив рядом то, ради чего его закрывали. Порядок
работы меняется на один шаг: сначала свой результат, потом открыть
эталон **в файл** и сверить обычным `compare_csv.py`.

```
> python tools\vault.py open program\P1\data\ref_by_store.csv --attempt program\P1\work\<ваш файл> --to program\P1\data\unlocked\ref_by_store.csv
> python program\M3\data\compare_csv.py program\P1\work\<ваш csv> program\P1\data\unlocked\ref_by_store.csv
```

Каталог `unlocked/` — в `.gitignore`: расшифрованный эталон остаётся на
диске и в репозиторий не возвращается.
