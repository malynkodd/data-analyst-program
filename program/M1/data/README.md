# Сквозной датасет модуля M1

Синтетика. Используется без изменений во всех трёх шагах M1
(M1.1–M1.3) — правило части 1.3 скилла curriculum-design: один датасет
на модуль, объявлен один раз, не меняется между шагами.

Все команды в шагах M1 — только вызовы предоставленных Python-скриптов
(`generate_clients.py`, `count_active.py`, `peek_clients.py`,
`check_order.py`), без `grep`/`awk`/`stat`/других POSIX-специфичных
инструментов — решение 13, `design/decisions.md`. Команда может
называться `python3` или `python` в зависимости от установки (M0
фиксирует, какая именно на вашей системе) — в шагах используется
`python3`, замените на свою, если нужно.

## Файлы

| Файл | Роль |
|---|---|
| `generate_clients.py` | Генератор. Детерминирован: `SEED = 20260701`, `REFERENCE_DATE` зашита как `2026-07-01`, а не берётся из системных часов. Перегенерация тем же интерпретатором Python даёт побайтово тот же файл. |
| `clients.csv` | Сгенерированный датасет, 240 строк, зафиксирован в репозитории как эталон — на него ссылаются все критерии готовности M1. |
| `count_active.py` | Готовый инструмент подсчёта, используется в M1.2. Учащийся его запускает (умение I2 из M0 — «запустить скрипт»), не пишет. |
| `peek_clients.py` | Готовый инструмент фильтрации/просмотра, используется в M1.1 — замена `grep`+`awk` (решение 13). |
| `check_order.py` | Кросс-платформенная проверка порядка двух файлов по mtime. В M1.2 больше не используется как критерий готовности (решение 14 — механизм заменён на `git log`, см. `step-02.md`); остаётся в репозитории как рабочий пример инструмента для решения 13 и как запасной вариант там, где Git недоступен. |
| `reference_answers.md` | Предвычисленные контрольные числа для самопроверки без запуска кода. |

## Схема `clients.csv`

| Колонка | Смысл | Особенность |
|---|---|---|
| `client_id` | Идентификатор | `C0001`…`C0240` |
| `registration_date` | Дата регистрации | 30–730 дней до REFERENCE_DATE |
| `plan_status` | Формальный статус подписки | `active` / `trial` / `paused` / `cancelled` |
| `last_login_date` | Дата последнего входа | пусто не бывает |
| `last_payment_date` | Дата последнего платежа | пусто у всех `trial` (пробный период не предполагает оплаты) и у части `paused`/`cancelled` |

Распределение статусов в зафиксированном файле: `active` 112, `cancelled`
67, `paused` 40, `trial` 21 (сумма 240).

## Три эталонные оси неоднозначности вопроса «сколько у нас активных клиентов»

Эти три оси — измерительный инструмент для M1.1–M1.3: по ним проверяется,
покрывают ли уточняющие вопросы учащегося неоднозначность, а не задают ли
вопрос не по существу.

1. **Ось времени** — за какой период считать активность (последние 30 /
   60 / 90 дней, или вообще без ограничения по времени, «пока не отменил»).
2. **Ось источника сигнала** — определять активность по формальному полю
   (`plan_status == active`) или по факту действия (`last_login_date`,
   `last_payment_date`).
3. **Ось состава базы** — включать ли в подсчёт `trial` и `paused`, или
   считать только «чистый» `active`.

Готового текстового вопроса, покрывающего все три оси одним предложением,
не существует специально: A5 требует именно **трёх раздельных** вопросов.

## Почему без sha256 и без снапшота

Правило снапшота (файл + дата выгрузки + sha256) в части 5 blueprint
относится к **реальным** источникам (P3, P4, P6). Здесь датасет
синтетический, и правило раздела 1.3 curriculum-design для синтетики —
другое: эталон фиксируется генератором с зашитым `SEED`, а не хэшем
выгрузки, которая может измениться.

## Категория датасета

M1 — сквозной модуль вне проектной привязки (не ведёт ни к одному
P1–P6 напрямую, обслуживает умения перед каждым проектом — часть 3.1
blueprint). При первом написании этого пилота раздел 1.3 скилла делил
датасеты только на «ведущие к P1/P2/P5» и «ведущие к P3/P4/P6», и для
M1 не находилось формальной категории — решение трактовать его по
аналогии с P1/P2/P5 было временным. Это исправлено в скилле: третья
категория «сквозные модули вне проектной привязки — синтетика по
умолчанию» добавлена в `curriculum-design/SKILL.md`, раздел 1.3.
`clients.csv` — образец именно этой категории.
