# M1.00. Декларация модуля (умения, датасет, шаги)

Не шаг для учащегося — служебный файл, требуемый разделом 1.3 скилла
curriculum-design: датасет и состав модуля объявляются один раз, до
первого содержательного шага. Написан задним числом при ревью пилота
(изначально M1 был написан без отдельного `step-00.md`, декларация была
размазана по `data/README.md`); правило на будущее — шаг 0 пишется
первым, а не восстанавливается после того, как остальные шаги готовы.

## Умения модуля и их шаги

Модуль M1 закрывает A5 и H2 (часть 2.2 blueprint), 12.5–16 ч.

| Умение | Часть умения | Шаг | Часы |
|---|---|---|---|
| A5 | Часть 1 из 3: 3 уточняющих вопроса по неоднозначному бизнес-вопросу, два кейса на разных базах | `step-01.md` | 3.5–4 |
| A5 | Часть 2 из 3: письменная фиксация определения до расчёта, демонстрация чувствительности к определению | `step-02.md` | 3.5–4.5 |
| H2 | Первое, вводное закрытие (называет 2 причины, вывод может быть неверным; плюс разбор чужого готового вывода); полностью — в M12 | `step-03.md` | 3–4 |
| A5 | Часть 3 из 3: отбрасывает запросы, ответ на которые не меняет ни одного решения | `step-04.md` | 2.5–3.5 |

Сумма: 12.5–16.0 ч при вилке части 6.1 blueprint 12.5–16.

**Вилка выросла с 8–10 ч контентным аудитом 2026-08-28 (решение 54).**
Аудит назвал у M1 самую низкую плотность практики в программе — 8
заданий на 8–10 ч — и один непокрытый переход: «вопрос → какое решение
изменится от ответа», то есть самую частую причину, по которой работа
junior-аналитика оказывается никому не нужной. Дописаны `step-04.md`
целиком, второй кейс в `step-01.md`, разбор чужого готового вывода в
`step-03.md`; разделы 1.7 всех четырёх шагов разложены на слагаемые по
образцу `M5/step-03.md`, чего в двух из трёх прежних шагов не было
вовсе. Заданий стало 22 против прежних 8.

**Оценка по-прежнему не измерена** (решение 24 `design/decisions.md`).
Совпадение суммы с вилкой по обеим границам — признак того, что вилка
поставлена по построчной сумме шагов, а не подтверждение оценок;
`check_module_hours()` печатает на этот случай `[WARN]`.

Строка M1 в части 6.1 помечена «**Требуется** — нет ни одного ориентира
ни в [М], ни в [К]»: у этого модуля нет внешнего аналога, к которому
можно приложить часы. Разрешит вопрос `research/self.md`, на 2026-08-28
пустой.

## Датасет модуля

**Категория:** сквозной модуль вне проектной привязки — синтетика по
умолчанию (третья категория раздела 1.3 curriculum-design, добавлена
2026-07-30 по итогам ревью этого же пилота).

**Файлы:** `program/M1/data/` — полное описание в `data/README.md`.
Сводка:

| Файл | Роль |
|---|---|
| `generate_clients.py` | Генератор `clients.csv`, детерминирован (`SEED=20260701`, `REFERENCE_DATE=2026-07-01`) |
| `clients.csv` | 240 строк, эталон для всех критериев готовности модуля |
| `count_active.py` | Подсчёт по параметризованному определению (M1.2) |
| `peek_clients.py` | Фильтрация/просмотр строк (M1.1) — кросс-платформенная замена `grep`+`awk` (решение 13) |
| `check_order.py` | Сравнение mtime двух файлов — резервный инструмент, в M1.2 не используется как критерий (см. решение 14: критерий теперь через `git log`) |
| `reference_answers.md` | Предвычисленные контрольные числа |

Датасет не меняется между `step-01.md`–`step-04.md`.

## Зависимости модуля

M0 — жёсткая зависимость (часть 3.2 blueprint, добавлено при написании
этого пилота): `step-01.md` использует терминал/скрипты (I2), `step-02.md`
использует `git commit` (решение 14, I1 частично). Без прохождения M0
шаги M1 не выполнимы буквально, не только желательны.
