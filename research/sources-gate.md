# Гейт источников

Проверка проводилась 29–30 июля 2026 г. (по времени серверов — ответ НБУ
датирован 30.07.2026, лента Prozorro — 29.07.2026 22:27 +03:00).
Проверялась **только доступность**, а не пригодность конкретного датасета.
Отбор файлов и проверка дефектов — Фаза 2.

Требование, против которого проверяли (blueprint, часть 5):
публичный доступ без логина; выгрузка воспроизводима (прямая ссылка или
открытый API); ≥50 тыс. строк хотя бы у одного из источников проекта.

Все проверки — `curl` из этой среды (не из Украины) плюс независимый
fetch для спорных случаев. Где источник заблокирован по географии, это
отмечено отдельно: «не отвечает отсюда» ≠ «не работает». **Все шесть
доменов, отдавших 403, перепроверены 29.07.2026 из браузера в Украине —
результат в §5а: живы все шесть.**

## 1. data.gov.ua — портал открытых данных

**Пригоден.**

- Домен отвечает: `GET https://data.gov.ua/` → **200**, 38 КБ, text/html.
- Открытый API: CKAN 3. `GET /api/3/action/package_list` → **200**,
  application/json, 1 518 697 байт (список всех датасетов одним ответом).
  `package_search?rows=0` → **count: 36 911** датасетов.
- Логин **не нужен**. Проверено скачиванием:
  `.../resource/3c38a6be-.../download/plan-zakup` → 200, 62 585 байт,
  файл распознан как «Microsoft Excel 2007+». Никаких редиректов на
  авторизацию.
- Прямые ссылки на файлы есть у каждого ресурса, формат в метаданных.
  Форматы в выдаче: XLSX, XLS, CSV, JSON, XML, ZIP, DOC.
- Объёмы: от единиц КБ (муниципальные таблички) до
  **ЄДР юридичних осіб** (Минюст, id `03cc1239-3988-4451-aa0d-aadb77448714`)
  — два ZIP на **326 477 353** и **470 316 770** байт.
- Документация: CKAN-овская, живая (`/api/3/action/help_show?name=...`
  отдаётся в каждом ответе).
- Лимиты/капча: не встретились. Пагинация — стандартная CKAN
  (`rows`/`start`).
- **Важно про robots.txt.** Блок `User-agent: *` → `Allow: /`,
  `Content-Signal: search=yes, ai-train=no, use=reference`. Но отдельными
  блоками запрещены ClaudeBot, GPTBot, CCBot, Bytespider, Amazonbot,
  Google-Extended, meta-externalagent и др. То есть **автоматическому
  AI-краулеру ходить нельзя**, скрипту студента на своём User-Agent —
  можно. Для программы это значит: выгрузку делает учащийся, а не агент.
- Замечено: часть датасетов ведёт на региональные CKAN-инстансы
  (`data.loda.gov.ua`, `data.dniprorada.gov.ua`, `opendata.gov.ua`) —
  отдельные хосты, их живость надо проверять поштучно на Фазе 2.

## 2. API курсов валют НБУ

**Пригоден.**

- `GET https://bank.gov.ua/NBUStatService/v1/statdirectory/exchange?json`
  → **200**, application/json, 5 549 байт, курсы на дату.
- Временной ряд: `.../NBU_Exchange/exchange_site?start=20200101&end=20241231&valcode=usd&sort=exchangedate&order=desc&json`
  → **200**, 378 118 байт, **1 827 записей** (5 лет по одной валюте).
- Логин не нужен, ключа нет, капчи нет.
- Формат: JSON. Кодировка UTF-8. Поля `exchangedate`, `cc`, `rate`,
  `units`, `calcdate`.
- Документация: `https://bank.gov.ua/ua/open-data/api-dev` → **200**,
  251 КБ, **88 примеров URL** — живая, с примерами по каждому набору.
- Другие рабочие наборы (проверены): `budget?period=m&json` → 200,
  **4 813 090** байт; `key?json` (учётная ставка) → 200, **6 574 673** байта.
- **Оговорка:** часть эндпоинтов из каталога возвращает **400** при
  подстановке параметров «как в примере»:
  `inflation?period=m&json` → 400, `banksfinrep?date=20240401&json` → 400.
  Значит, формат параметров у отдельных наборов свой — нужна сверка с
  документацией по каждому. На доступность источника это не влияет.
- Лимитов при последовательных запросах не встретили.

## 3. Prozorro — открытые данные закупок

**Пригоден.**

- Два хоста, оба **200**, ответы идентичны:
  `https://public.api.openprocurement.org/api/2.5/tenders`
  и `https://public-api.prozorro.gov.ua/api/2.5/tenders`.
- Логин не нужен, ключа нет, капчи нет.
- Формат: JSON. Карточка тендера — 5 401 байт.
- Живость данных подтверждена: `?descending=1` вернул записи с
  `dateModified` **2026-07-29T22:27:26+03:00** — то есть текущие минуты.
- **Это лента изменений, а не дамп.** Пагинация — курсором
  `next_page.offset`, `limit` до 100. Но лента управляемая:
  - `offset=2025-01-01T00:00:00` — старт с произвольной даты, работает;
  - `descending=1` — с конца;
  - `opt_fields=title,value,status,procuringEntity,tenderID,dateCreated`
    — поля отдаются **прямо в ленте**, без отдельного запроса на каждый
    тендер. Это снимает главное возражение против источника: не нужно
    2 млн запросов, достаточно обхода окна.
- Скорость: 10 страниц по 100 записей = **1 000 записей за 4 секунды**
  (~7 запросов/с), ни одного 429. Троттлинга не обнаружено.
  Ориентир: 50 тыс. строк ≈ 500 страниц ≈ 3–4 минуты.
- Отдельные ленты того же API, все **200**: `/tenders`, `/contracts`,
  `/plans`, `/agreements`. Для P4 это уже три источника разной
  периодичности внутри одной системы.
- Документация: `https://prozorro-api-docs.readthedocs.io/uk/latest/`
  → **200**, 94 606 байт. Живая.
- Сопутствующее: `https://prozorro.gov.ua/` → 200 (842 байта, SPA-заглушка),
  `https://bi.prozorro.org/` → 200 (редирект на `/hub/`, Qlik — интерфейс,
  не API). Наборы «Prozorro» на data.gov.ua (**140** результатов) — это
  мелкие муниципальные выгрузки на 2–30 КБ, **не** массовый источник.
  Массовый источник — API.
- `prozorro.sale` (продажа активов): сайт 200, но
  `public-api.prozorro.sale` и `api.prozorro.sale` — **соединение не
  устанавливается** (код 000). Как источник не берём.

## 4. Держстат — stat.gov.ua (новый портал, SDMX API)

**Пригоден. Лучший источник по объёму из всех проверенных.**

- `https://stat.gov.ua/` → **200**, 77 789 байт.
- Открытый SDMX 2.1 REST API. Рабочая база:
  `https://stat.gov.ua/sdmx/workspaces/default:integration/registry/sdmx/2.1/`
- Логин не нужен, ключа нет.
  - `dataflow/all/all/latest` → **200**, 140 276 байт,
    **118 потоков данных**, агентство `SSSU`.
  - `codelist/all/all/latest` → **200**, **116 645 866 байт** справочников.
  - `data/SSSU,DF_EXTERNAL_TRADE_OF_GOODS,6.0.0/all/all` → **200**,
    19 931 513 байт за 4 с, **249 898 наблюдений**. Требование ≥50 тыс.
    строк выполнено с запасом одним запросом.
  - `data/SSSU,DF_DELIVERY_DAIRY_MATERIALS_PROC_MILK_PROD_A,1.0.0/all/all`
    → 200, 7 410 825 байт, 10 161 наблюдение.
- Формат: SDMX-ML (XML), `application/vnd.sdmx.structure+xml;version=2.1`.
  **Заголовок `Accept: application/vnd.sdmx.data+csv` игнорируется** —
  отдаётся тот же XML. Значит, парсинг XML обязателен; для программы это
  не минус, а материал для модуля по разбору данных.
- **Дефекты доступности, которые надо знать:**
  - `data/SSSU,DF_EXTERNAL_TRADE_INDIVIDUAL_GOODS_BY_COUNTRIES,3.0.0/all/all`
    → **500** через 30 секунд. То есть не каждый поток отдаётся целиком,
    крупные надо резать по ключу.
  - Ссылки в меню документации битые: `/uk/sdmx-api-v2-1` и
    `/uk/sdmx-api-v3` → **404**. Рабочие адреса —
    `/uk/development-api/sdmx-api-v2-1` и `/uk/development-api/sdmx-api-v3`
    (**200**, 77 502 байта, с полным описанием ресурсов и параметров).
    В файле курса надо давать рабочий адрес, а не тот, что в меню.
  - `https://ess.stat.gov.ua` (упоминается на страницах портала) — это
    **не** SDMX API, а «Пошук форм ДСС за ЄДРПОУ», отвечает **401**,
    требует логин. Как источник не годится.
- Версии потоков разбегаются от `1.0.0` до `16.0.0` — косвенный признак,
  что схема между периодами менялась. Это **не проверено**, гипотеза для
  Фазы 2.

**Что это меняет и что не меняет.**

Меняет: источники не мёртвые, и для учащегося в Украине они доступны.
Статус в blueprint — **«доступно из UA, недоступно извне»**, резерв.

Не меняет решения не строить на них P3, P4, P6. Три причины:

1. Требование части 5 blueprint — воспроизводимая выгрузка. Учащийся может
   находиться вне Украины (релокация — прямая тема M14), и там выгрузка не
   воспроизводится вовсе.
2. Правило 3 CLAUDE.md — каждая ссылка проверяется fetch'ем. Для этих
   доменов автоматическая проверка ссылок при поддержке программы
   невозможна: из среды агента приходит 403 независимо от User-Agent.
   Проверять их можно только руками из украинского браузера, каждый раз.
3. Замена уже найдена и по объёму сильнее: Prozorro API и Держстат SDMX.

Что осталось непроверенным: формат, объём, документация и лимиты
API этих порталов. Известно только, что `api.spending.gov.ua/api/v2/api/
transactions/` отвечает 400 с `application/json`, то есть API-хост жив.
Если Фаза 2 упрётся в нехватку дефектов в данных, бюджетные источники —
первый кандидат на возврат, и проверять их надо из Украины.

## 9. Потолок агента на выгрузку — это robots.txt источника, не техника; отдельно измерен потолок WebFetch (2026-08-22)

Вопрос возник при закрытии P4: почему снапшот P3 (§2, §3) агент выгрузил
сам (`program/P3/data/fetch_nbu.py`, `fetch_prozorro.py`, `urllib.request`
из Bash), а для ЄДР P4 выгрузку должен делать автор. Разбор — решение 36,
`design/decisions.md`. Здесь — сама проверка.

**robots.txt по каждому источнику проекта:**

| Источник | robots.txt против AI-краулеров | Проверено |
|---|---|---|
| data.gov.ua | Да — именные блоки `ClaudeBot`, `GPTBot`, `CCBot` и др. (§1) | 29.07.2026 |
| bank.gov.ua (API НБУ) | Не встречено | использовался напрямую при выгрузке P3 |
| Prozorro API | Не встречено | использовался напрямую при выгрузке P3 |
| stat.gov.ua (Держстат SDMX, P6) | **Нет** — только общий `User-agent: *`, `Crawl-delay: 5`, список закрытых путей без SDMX-эндпоинтов, никаких именных AI-блоков | 22.08.2026, fetch `stat.gov.ua/robots.txt` |

Вывод: агенту нельзя выгружать с `data.gov.ua` (сайт явно об этом просит),
но нет найденного запрета на `stat.gov.ua` — если для P6 понадобится,
агент технически может выгрузить исходники Bash-скриптом, как в P3.

**Отдельно — измеренный потолок инструмента WebFetch, не связанный с
robots.txt.** `WebFetch` — не HTTP-клиент, а инструмент, пропускающий
контент через модель-суммаризатор («small, fast model») и прямо
заявляющий: «Results may be summarized if the content is very large».
Проверено на заведомо разрешённом источнике (`stat.gov.ua`, без AI-блока
по таблице выше): запрошен `data/SSSU,DF_DELIVERY_DAIRY_MATERIALS_PROC_MILK_PROD_A,1.0.0/all/all`
— по §4 задокументирован как 7 410 825 байт, 10 161 наблюдение. Ответ
`WebFetch` оборван буквально посреди тега (`<Obs TIME_PERIOD="2025"
OBS_FLAG="0"/></Se`), уцелело ≈180–200 `<Obs>` из 10 161 — около 2%.
Точный порог не измерен (нужен бинарный поиск, не делался), но заведомо
меньше 7,4 МБ — на два порядка меньше 326 МБ `UO.zip` P4.

Все объёмы в этом файле, кроме этой проверки, получены `curl` (см. начало
файла: «Все проверки — curl из этой среды»), поэтому обрезка `WebFetch`
не затронула ни одну цифру гейта, использована только для этой
конкретной проверки инструмента.

**Практический вывод для P6 и для всех крупных источников:** `WebFetch`
годится для проверки доступности/формата страницы, не годится для
выгрузки или сверки объёма данных крупнее единиц МБ — там нужен
`curl`/`urllib` в Bash. Это техническое ограничение действует независимо
от того, что разрешает `robots.txt`.

## Прямой ответ: хватает ли живых источников на три проекта

**Да, хватает. Ни один из P3, P4, P6 на синтетику возвращать не надо.**

Живых источников, полностью удовлетворяющих требованию blueprint
(публичный доступ без логина + воспроизводимая выгрузка), набралось
**четыре основных и два вспомогательных**:

основные — data.gov.ua, API НБУ, Prozorro API, Держстат SDMX;
вспомогательные — ukrstat.gov.ua (старый) и API НАЗК.

Требование «≥50 тыс. строк хотя бы у одного источника проекта» закрыто
дважды и фактически, а не оценочно: Держстат SDMX отдал **249 898**
наблюдений одним запросом, Prozorro API даёт 50 тыс. строк за ~4 минуты
обхода ленты.

Раскладка по проектам:

- **P3** (дашборд вместо рассылки; тендеры + курсы) —
  Prozorro API + API НБУ. Оба живые, оба без логина, у обоих живая
  документация. Снапшот с датой и sha256 делается тривиально.
- **P4** (три источника, один объект) — Prozorro API (ленты `tenders` и
  `contracts` — разная периодичность) + data.gov.ua (ЄДР для сверки
  контрагентов по ЄДРПОУ, ZIP на 326 и 470 МБ) + API НБУ (курсовой ряд).
  Три источника, три формата: JSON / ZIP-выгрузка / JSON. Требование
  «разные форматы и разная периодичность» выполнено.
  **Объём ЄДР решён** — решение 35, `design/decisions.md`, 2026-08-22:
  `UO.zip` (юрлица), полностью, без подмножества, 326 858 701 байт на дату
  решения. Выгружает автор вручную — решение 36 объясняет почему
  (`robots.txt` `data.gov.ua` запрещает AI-краулерам, не техническое
  ограничение, см. §9 этого файла).
- **P6** (capstone, спрос и цена по региону) — Держстат SDMX как основа
  (внешняя торговля 249 898 наблюдений; есть потоки по продажам и
  запасам товаров в опте, по ценам, по регионам) + API НБУ. Плюс
  ukrstat.gov.ua как источник заведомо грязных Excel-файлов, если по
  условиям проекта нужен ещё один слой расхождений.

**Что выпало из списка blueprint.** Из пяти кандидатов, названных в
части 5, **два не прошли**: «открытый бюджет» (openbudget.gov.ua) и
Є-Дата (spending/edata) — оба отдают 403 с Akamai с двух независимых
точек выхода вне Украины. Перепроверка из украинского браузера 29.07.2026
(§5а) показала, что порталы живы и наполнены, поэтому статус — не «мертво»,
а «доступно из UA, недоступно извне». Из списка опор для P3, P4, P6 они
вычеркнуты (воспроизводимость + правило 3 CLAUDE.md), в резерве оставлены.
Замена найдена и проверена: роль «данных о публичных финансах» закрывает
Prozorro API, роль «официальной статистики» — Держстат SDMX, который в
blueprint фигурировал только как «публикации Держстату» и на деле
оказался сильнее, чем предполагалось (полноценный SDMX API вместо
скачивания Excel-файлов).

**Что осталось непроверенным и уходит в Фазу 2.** Наличие в данных
≥3 дефектов из списка blueprint (несогласованные справочники, смена
схемы между периодами, кириллица не в UTF-8, пропуски в календарных
рядах, дубли ключа, разные единицы измерения) — **не проверялось**, это
задача отбора конкретных датасетов. Фактически подтверждён пока только
один дефект: windows-1251 в файлах ukrstat.gov.ua. Версии потоков
Держстата (от 1.0.0 до 16.0.0) намекают на смену схемы между периодами,
но это гипотеза, а не проверенный факт.
