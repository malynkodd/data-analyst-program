# Data Analyst Program

Программа самостоятельного обучения аналитике данных с нуля до первой
оплачиваемой работы на украинском рынке. Текст, датасеты и проверочные
скрипты — всё в этом репозитории, всё проходится в одиночку, без ментора
и без второго человека.

**Этот файл — точка входа для того, кто программу проходит.** Файлы
`CLAUDE.md`, `HANDOFF.md`, `design/`, `research/` и `audit/` написаны для
того, кто её пишет; читать их для прохождения не нужно.

Объём — **531–672 ч**. При 25 ч/нед это 22–27 недель (5–6 месяцев), при
10 ч/нед — 54–68 недель (12–15 месяцев). Срок поиска работы сверх этого:
данных нет, и обещаний здесь не будет.

## 2. Порядок прохождения

Идти сверху вниз. Внутри этапа — в порядке колонки «Что входит»;
внутри модуля — по номерам шагов, начиная со `step-00.md`.

| Этап | Что входит | Часы |
|---|---|---|
| 1. Основание | M0 Терминал, M1 Постановка задачи, M13a Гео-фильтр (диагностика), выбор домена, старт английского | 26–31 |
| 2. Данные в руках | M2 Таблицы, M3 SQL, M10 Git, **P1**, **P2** | 144–184 |
| 3. Показать | **R1**, M4 Power BI, M15 Tableau, M7 BigQuery, M16 Looker Studio, M12 Деливерабл, **P3** | 93–124 |
| 4. Автоматизировать | **R2**, M5 Python, M6 Грязные данные, **P4** | 108–135 |
| 5. Специализация | **R3**, M8 Метрики, M9 Статистика-ловушки, M11 Доменный пакет, **P5** | 104–128 |
| 6. Выход | **R4**, M13b Гео-фильтр (полный), M14 ФОП / ступень 2, **P6**, **R5**, сборка резюме и профиля | 58–72 |

- **M0–M16** — модули, `program/M0/` … `program/M16/`.
- **P1–P6** — проекты портфолио, `program/P1/project.md` … `program/P6/project.md`.
- **R1–R5** — возвратный контроль, `program/review/step-01.md` …
  `step-05.md`. Новых умений не несут: перепроверяют закрытые раньше,
  вхолодную, с расширяющимся интервалом. Пропустить их — значит
  отказаться от единственного измерения удержания, которое в программе
  есть.
- Сборка резюме, GitHub-профиля и трекера откликов — `program/career/`.

Порядок не произвольный: карта зависимостей — `design/blueprint.md`,
часть 3.1. M7 (BigQuery) стоит в этапе 3 перед M16 (Looker Studio),
потому что отчёт M16 строится поверх таблицы, которая создаётся в M7.

## 3. Как устроен шаг

Каждый содержательный шаг — один файл `step-NN.md` с восемью разделами:

| Раздел | Что в нём |
|---|---|
| шапка | умение, что требуется до этого, какие файлы шаг создаёт, часы |
| 1.1 | зачем шаг и какое умение закрывает |
| 1.2 | теория своими словами |
| 1.3 | разобранный пример на датасете модуля, с настоящим выводом |
| 1.4 | **задание** — то, что вы делаете руками |
| 1.5 | **критерий готовности** — механическая проверка «да/нет» |
| 1.6 | типичные ошибки, каждая с признаком в вашем результате |
| 1.7 | честная оценка времени, разложенная на слагаемые |
| 1.8 | вопрос уровня собеседования |

Шаг сдан, когда сходится раздел 1.5, а не когда прочитан раздел 1.2.
Критерий почти всегда — прогон скрипта из `data/` того же модуля:
`compare_csv.py`, `check_*.py`, `pytest`. Сверяется код возврата и текст
вывода, а не «на вид похоже».

`step-00.md` — декларация модуля: умения, датасет, состав шагов, часы.
Читается первым, заданий не содержит.

## 4. Если не сошлось

Порядок ровно такой, по убыванию дешевизны:

1. **Раздел 1.6 того же шага.** Там разобраны ошибки, измеренные на этих
   данных при написании шага, и у каждой назван признак, по которому её
   видно в вашем результате. Начинать надо отсюда, а не с переписывания
   кода вслепую.
2. **Блок «Справочник» того же шага** — ссылки на документацию под ту
   конструкцию, которой не хватило.
3. **Поиск снаружи — можно.** Интернет, ИИ-ассистент, чужой код. Это не
   нарушение: теория в шагах сокращена намеренно (`design/decisions.md`,
   решение 28) в расчёте на добор поиском. Но каждое такое обращение
   пишется отдельной пометкой `[сторона] что искал` в журнале (раздел 5).
   Если пометок выходит больше одной на шаг — сокращение зашло слишком
   далеко, и это дефект программы, а не ваш.

Проверка уже написанного ответа (в том числе вердикт ИИ по разделу 1.5)
пометки `[сторона]` не получает — она помечается `[проверка]`.

## 5. Журнал часов: `research/self.md`

Одна строка на сессию, в конце сессии, не в конце недели:

```
Дата | Тема | План (ч) | Факт (ч) | Факт: задания (ч) | Где застрял | Что оказалось лишним
```

Полные правила — в шапке самого `research/self.md`. Три, без которых
файл бесполезен:

- **Факт — фактическое время**, округление до 0.25 ч вниз, перерывы не
  считаются.
- **«Факт: задания» — часть «Факта», а не добавка к нему:** сколько из
  него ушло на раздел 1.4 и доведение 1.5 до сходимости. Без этого
  разделения вилки шагов не калибруются.
- **Пропущенный день пишется как пропущенный (0 ч).** Простои — часть
  честного календаря.

Это не дневник для настроения. 22 из 25 часовых вилок программы стоят с
пометкой «требуется калибровка», и снять её может только этот файл.

## 6. Эталоны за турникетом

Часть разборов и ответов закрыта: файл лежит на диске зашифрованным
(`*.enc`) и открывается **после** сохранённой попытки, а не вместо неё.

```
> python tools\vault.py open <путь к эталону> --attempt <путь к вашему файлу>
```

Например:

```
> python tools\vault.py open program\M9\data\exam.py --attempt program\M9\work\exam_answers.md
```

Без файла попытки турникет отказывает и говорит об этом прямо. Каждое
открытие пишется строкой в `research/attempts.md` — не для контроля, а
чтобы на выпуске было видно, что вы сдали сами, а что подсмотрели.

## 7. Приложение для прохождения

`app/` — локальное веб-приложение: показывает те же `step-*.md`,
запускает те же `check_*.py`, ведёт таймер и само дописывает строку в
`research/self.md`. Содержания в себе не держит и часов программе не
добавляет. Запуск и устройство — `app/README.md`. Проходить можно и без
него, из терминала.

## 9. Чего программа про себя не знает

Читать до старта, чтобы не принять ограничение за поломку:

- **Часы не измерены.** 22 из 25 вилок — проектные оценки. Ваш первый
  прогон и есть их калибровка.
- **Четыре инструмента не прогнаны автором** — Tableau (M15), Looker
  Studio (M16), BigQuery (M7) и Power BI на реальных данных P3. Пути в
  меню взяты из официальной документации, не с экрана. Подробно —
  `DEFERRED.md`.
- **Банк вакансий M13 протухает по календарю.** Средний срок жизни
  вакансии — 4–8 недель; ссылки собраны один раз.
- **Пороги сдачи возвратных точек** (80 % и 50 % сошедшихся заданий для
  R1–R4, 19 и 15 из 22 для R5) назначены, а не измерены.
