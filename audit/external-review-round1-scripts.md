**`program/M1/data/check_order.py` — НАСТОЯЩИЙ ДЕФЕКТ, класс R32.**
Запуск: `python check_order.py <earlier> <later>`. При правильном порядке
печатает `OK: ...`; при неправильном — печатает `FAIL: ... is NOT older
than ...`, **но не вызывает `sys.exit(1)`** ни в одной ветке. Прогнано
дважды (файлы созданы вне git, во временных именах, удалены после):
```

_neg_a.txt: 1787306310.8180444
FAIL: _neg_b.txt is NOT older than _neg_a.txt
код возврата: 0
```
Тот же класс, что заявлен пунктом 1 задания: текст утверждает провал, код
возврата утверждает успех. Сейчас `check_order.py` не служит единственным
механизмом ни одного критерия готовности (решение 14: критерий M1.2
переписан на `git log`/`git show`; `check_order.py` остаётся в репозитории
как «пример инструмента для решения 13», упомянут в `M1/step-00.md` и
`M1/data/README.md`, но не в живом тексте шага). Это снижает цену дефекта,
но не отменяет его: инструмент с контрактом «печатает OK/FAIL» обязан
транслировать этот вердикт в код возврата, иначе любой будущий шаг,
который начнёт полагаться на код возврата этого скрипта (а не на текст),
получит тот же R32.

**`program/M9/data/traps_a.py`…`traps_d.py`, `exam.py`** — не проверки в
