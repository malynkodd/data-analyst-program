# Аудит глазами студента — 2026-09-03

Вопрос этого прохода один: **можно ли по этому тексту научиться, читая
его как человек без опыта, у которого нет ментора.** Не «что написано» и
не «как написано» (это `audit/readability-pass-2026-08-28.md`), а
«дойду ли я от первой строки до критерия готовности, не застряв».

Метод: чтение шагов подряд в порядке прохождения — 1.2 → 1.3 → 1.4 →
1.5 — плюс механические проверки по всем 95 содержательным шагам.
Каждое утверждение ниже подтверждено прогоном; команды приведены.

---

## 0. Короткий вердикт

**Учиться по этому можно.** Механика в рабочем состоянии: данные на
месте, скрипты запускаются, эталоны сходятся с текстом, критерии
проверяются без второго человека. Это редкость, и это проверено
прогонами, а не на глаз (раздел 3).

**Но у программы нет входа для студента, и три места ломают прохождение
по календарю.** Всё, что нужно знать до первой команды — с чего начать,
в каком порядке идти, что установить, можно ли гуглить, как открыть
эталон, — лежит в файлах, написанных для проектировщика:
`design/blueprint.md`, `design/decisions.md`, `research/self.md`. Файл,
который студент откроет первым, — `README.md` в корне — пуст.

## 2. Мешает, но обходится

### 2.1. Календарь в 6.3 посчитан от устаревшего итога

`design/blueprint.md`, 6.3:

> **10 часов в неделю: 51–65 недель — это 11–15 месяцев.**
> **25 часов в неделю: 21–26 недель — это 4–6 месяцев.**

Действующий итог программы — 529–670 ч (та же 6.2, `CLAUDE.md`):

```
529/10 = 52.9 → 53      670/10 = 67.0 → 67
529/25 = 21.2 → 22      670/25 = 26.8 → 27
```

То есть 53–67 и 22–27, а не 51–65 и 21–26. Числа 6.3 получены из
прежнего итога 511–650 (до решения 54). Там же в 6.2 стоит выкладка
`511/10 = 51.1→52, 650/10 = 65.0→65`, а в 6.3 — «не входящие в
460–588», итог ещё двух решений назад. Три разных устаревших итога в
одном разделе; `check_consistency.py` их не ловит.

Студент по этой таблице планирует свой год.

### 2.2. Чем работать в M2 — не сказано

`program/M2/step-00.md` не содержит слова «Excel» ни разу:

```
> grep -c "Excel" program/M2/step-00.md
0
```

При этом сами шаги требуют `XLOOKUP`, `SUMIFS`, `SUMPRODUCT`, `$A$1`,
сводные с двумя измерениями и экспорт диаграммы картинкой. `XLOOKUP`
есть в Microsoft 365 и Excel 2021+ и в Google Sheets; в Excel 2019 и
старее его нет. Ни продукт, ни версия, ни допустимая замена нигде не
названы:

```
> grep -rn "Excel 20|Microsoft 365|версия Excel" program/ research/
(только два упоминания в research/sources-gate.md, про формат файла)
```

Решение 21 обязывает называть окружение автора — версию и путь. Для
Python, `sqlite3`, PostgreSQL и Power BI это сделано. Для инструмента
второго по размеру модуля (35–46 ч) — нет.

Смягчающее: критерий `M2/step-04.md` не требует именно `XLOOKUP`
(«3 задачи решены без ошибки формулы»), а `INDEX`+`MATCH` разобран в том
же шаге и работает везде. То есть обойти можно — но студент об этом
узнает, только когда формула не найдётся.

## 3. Проверено прогоном и оказалось в порядке

Это не вежливость: каждая строка ниже — прогон, который мог упасть.

**1. Разобранные примеры сходятся с данными дословно.** `M0/step-02.md`:

```
> python view_head.py orders_log.csv        первые 5 строк — те же
> python count_lines.py orders_log.csv      rows in file: 500
> python count_lines.py orders_log.csv --status shipped   304
> python find_row.py orders_log.csv --contains damaged --limit 3
D0008 / D0019 / D0040, total matches: 47
```

Все числа и все строки совпали с 1.3 посимвольно.

**2. Учебная таблица `ROW_NUMBER` / `RANK` / `DENSE_RANK` (`M3/step-06.md`,
1.2) сошлась с базой построчно** — все десять строк, все три колонки.
Это тот случай, где неверная таблица научила бы неверному, и она верна.

**3. Скрипты, названные в шагах, существуют.** 400 упоминаний, ни одного
битого: отсутствуют только те файлы, которые студент пишет сам
(`run.py`, `test_metrics.py`, `check_rules.py`) и которые закрыты
турникетом (`exam.py.enc`).

**4. Установка инструментов, где она есть, сделана по-настоящему.**
`sqlite3` — четыре пункта, размер архива, правка `PATH` на уровне
пользователя, отдельная оговорка, что клиент и библиотека Python — разные
программы и одна не заменяет другую. Это написано человеком, который сам
на это наступил.

**5. Турникет работает и отказывает правильно** — без файла попытки не
открывает, проход пишет в `research/attempts.md`.

**6. Объём чтения честный.** 163 787 слов на 95 содержательных шагов,
в среднем 1724 слова на шаг: 15–23 ч одного прохода при 529–670 ч
программы, 3–4%. Раскладка 1.7 закладывает на чтение больше — запас на
перечитывание есть, и вилки шагов от этого не рассыпаются.

**7. Маршрут «не сошлось» есть в 94 шагах из 95**, и в каждом ошибки
названы с числом, по которому их видно в своём результате. Это главное,
что делает программу проходимой без ментора.

**8. Критерии концептуальных шагов сведены к сопоставлению, а не к
суждению.** `M1/step-01.md`, 1.5: три эталонные оси, порог ≥2 из 3,
запрещённая категория вопроса, обязательная пара чисел из
`reference_answers.md`. Проверять себя есть чем даже там, где считать
нечего.
