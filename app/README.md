# Приложение для прохождения программы

Локальное веб-приложение: читает уже написанные шаги `program/**/step-*.md`,
запускает существующие `program/**/data/check_*.py`, ведёт таймер сессии и
дописывает строку в `research/self.md`. Содержание программы в приложение
не переносится — оно читается с диска на каждый запрос
(`app/PLAN.md`, раздел 0). Решение, которым приложение заведено, — 40
(`design/decisions.md`).

## Установка

Отдельное окружение, а не `.venv` в корне: тот принадлежит модулю M5, его
состав (22 пакета, 243 МБ) измерен и процитирован в `program/M5/step-01.md`,
и дописывать в него `flask` значило бы испортить измерение.

```
> python -m venv app\.venv
> app\.venv\Scripts\python.exe -m pip install -r app\requirements.txt
```

## Ключ Anthropic API

```
> copy app\.env.example app\.env
```

Вписать в `app/.env` строку `ANTHROPIC_API_KEY=...`. Файл внесён в
корневой `.gitignore` — в репозиторий он не попадает никогда; коммитится
только `app/.env.example`.

Без ключа приложение работает целиком, кроме двух функций: чат ассистента
и вердикт ИИ по критерию отвечают ошибкой «ключа нет». Дерево, рендер
шагов, запуск `check_*.py`, таймер и запись в `research/self.md` от ключа
не зависят.

## Запуск

```
> app\.venv\Scripts\python.exe app\server.py
```

Открыть `http://127.0.0.1:8765/`. Порт меняется флагом `--port`, адрес —
`--host`. Один процесс, один порт, наружу не слушает.

## Что делает

| Экран | Что | Где описано |
|---|---|---|
| стартовый | «Начать здесь» — первый незакрытый шаг; как устроен один шаг; таблица шести этапов с прогрессом | `app/PLAN.md`, 1.2 |
| дерево слева | шесть этапов части 6.2 blueprint в порядке прохождения; модули с человеческими названиями («M3 SQL»); поиск; ▣ — есть проверка скриптом, △ — нужен ручной прогон | 1.1 |
| шаг в центре | крошки «M4 Power BI · шаг 5 из 5», чипы с часами и умением, разделы карточками с подписями, «← →» между шагами | 1.3 |
| «Начал / Пауза / Закончил» | таймер сессии; при завершении открывается форма и пишется строка в `research/self.md` | 4 |
| «Проверить» | запуск той самой команды `check_*.py`, что написана в шаге, с дословным выводом; стоит сразу под критерием 1.5 | 3 |
| «Проверить по критерию» | сверка письменного ответа с разделами 1.5 и 1.6 того же шага | 5.2 |
| ассистент справа | вопрос по тексту текущего шага, три готовых вопроса для начала | 5.1 |
| «Как пользоваться» | окно с объяснением всего перечисленного; открывается само при первом запуске | — |

**Вердикт ИИ и результат скрипта различаются в интерфейсе и в журнале.**
Вывод скрипта помечен `РЕЗУЛЬТАТ СКРИПТА`, вердикт —
`ВЕРДИКТ ИИ ПО КРИТЕРИЮ 1.5 — НЕ РЕЗУЛЬТАТ СКРИПТА`, и в
`research/self.md` они пишутся разными пометками. Это разные по
надёжности вещи.

**Отложенные ручные прогоны.** Шаги M4, M15, M16, M7 и P3/P4 показывают
дословную строку из `DEFERRED.md` с припиской, что вердикт ИИ реального
прогона в Power BI Desktop, Tableau Public или Looker Studio не заменяет.

## Обращения к ассистенту попадают в журнал

Правило 6 `research/self.md` требует отдельной пометки на каждое
обращение на сторону. Решением 40 встроенный ассистент считается таким же
обращением, как внешний поиск: каждый вопрос и каждый запрос вердикта
копится в буфере шага и вклеивается в поле «Где застрял» при завершении
сессии. Без этого фальсификатор решения 28 («теория сокращена вдвое;
больше одного обращения на шаг — сокращение зашло далеко») перестал бы
что-либо мерить.

## Тесты

```
> app\.venv\Scripts\python.exe -m pytest app\tests -q
```

- `test_repo.py` — дерево строится из `design/blueprint.md` (части 6.1 и
  6.2), а не из своего списка: имена модулей, шесть этапов, порядок и
  разбор разделов шага;
- `test_runner.py` — вывод и код возврата `check_*.py` из приложения
  совпадают с прямым запуском в терминале (M0 — относительный путь,
  career — путь от корня);
- `test_journal.py` — дозапись в копию настоящего `research/self.md` не
  трогает ни одной существующей строки, поля и округление часов
  соответствуют правилам самого файла;
- `test_verdict.py` — промпт несёт разделы 1.5 и 1.6 дословно, вердикт
  всегда помечен как оценка ИИ; проверка «неверный ответ ≠ верный»
  обращается к настоящему API и **пропускается без ключа**.
